| 결정 | 텍스트 | ②. 엔카가 `RANK_A/B/C` 로 직접 준다 |

| STEP | 릴레이션 | ① STEP 14 |

### 실제 사례

| 결정 | 근거 |
|---|---|
| 가격 ±0% = 100/200 | 기대가는 평균값. 딱 맞으면 절반 |
| 배기량으로 차종 확정 | 제조사 사양이라 딜러가 못 바꾼다 |
| 2단 분류 유지 | 배기량은 상세 A 에만 있음. 1,364건 보호 |
| 전기차 보증 `-1` | 엔카가 전기차용 보증을 안 판다 |
| 보증 = 엔카 실측 우선 | 설정표는 사람이 넣어 틀린다 |
| 불명을 골격으로 안 봄 | E 는 되돌리기 어렵다 |

### 뷰

```

```

## 왜 이 구조인가

```
지금까지 문제는 '어디에 적혀 있는지 모르는 것' 이었다.

  · 같은 결함을 세 번 진단했다
  · 폐기한 규칙이 코드에 남아 있었다
  · '왜 이렇게 했지' 를 다시 물었다

문서를 늘리면 더 못 찾는다.
STEP 을 열면 그 STEP 의 결함·결정이 보여야 한다.
```

```
★ 노션에 옮긴 뒤 지시서 markdown 은 '원본' 으로만 둔다.
  두 곳을 동시에 고치면 반드시 어긋난다.
```
