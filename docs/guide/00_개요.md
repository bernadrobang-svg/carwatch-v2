## 한 줄

**중고차 매물을 자동으로 모아 같은 기준으로 점수를 매기고, 살 만한 것을 골라내는 시스템이다.**

## 왜 만드는가

중고차는 같은 차종·같은 연식이어도 매물마다 가격·주행거리·사고이력·옵션이 다르다.
사람이 수백 건을 비교하면 **기준이 흔들리고, 먼저 본 매물에 끌린다.**

```
목표   매물 수천 건을 같은 잣대로 점수화한다
       왜 그 점수인지 매 건 추적 가능하게 한다
       조건에 맞는 후보를 놓치지 않는다
```

**「좋은 차를 찾는 것」이 아니라 「기준을 일정하게 유지하는 것」이 목적이다.**

## 무엇을 다루는가

**1차는 로컬 Python 배치다. 데모 성격이며, 온라인 서비스 구조로 옮길 수 있게 만든다.**

## 전체 흐름

```
① 수집     엔카 API 에서 원문을 받아 그대로 저장한다
             목록 → 매물 목록과 시세 분포
             매물별 → 상세 · 성능점검 · 보험이력 · 진단
② 파싱     저장된 원문을 읽어 정규 필드로 옮긴다
③ 사전     원문에서 코드·이름 사전을 자동 생성한다
④ 분석     축별로 판정한다.  값 하나마다 「무엇을 근거로」를 함께 남긴다
⑤ 채점     축 점수를 합쳐 등급을 매긴다
⑥ 검증     5단계로 어긋난 곳을 잡는다
⑦ 출력     화면·리포트.  관심 매물은 계속 추적한다
```

**①과 ②를 분리하는 것이 이 설계의 핵심이다.**
원문을 보존하면 판정 규칙이 바뀌어도 **다시 받지 않고 다시 읽기만 하면 된다.**

## 이 문서가 특별히 경계하는 것

**v1 은 동작했으나 결과를 믿을 수 없었다. 원인은 코드 실력이 아니라 구조였다.**

| v1 에서 실제로 일어난 일 | 규모 |
|---|---|
| 공유 변수 하나 때문에 원문이 잘못된 라벨로 저장 | 2,183건 (98%) |
| 판정에 쓸 필드를 파싱은 하고 컬럼에 안 넣음 | 사고 20점이 한 번도 작동 안 함 |
| 사전을 손으로 적어 표기가 어긋남 (휀더/펜더) | 344건 미분류 |
| 판정 근거를 안 남겨 값이 왜 그런지 추적 불가 | 14축 중 12축 |
| 「저장했다」고 선언했으나 실제로는 전건 NULL | 9개 컬럼 |
| 딜러 상사명 컬럼에 지역명이 들어감 | 전건 |
| 근거 없는 숫자가 배점의 기반이 됨 | 가격 200점 |

**그래서 이 문서는 「잘 짜라」가 아니라 「잘못 짜이지 않도록 막는다」로 쓰여 있다.**

```
DTO 강제           어떤 필드를 쓰는지 시그니처에 드러난다
put(prio) 엔진      호출 순서가 결과를 바꾸지 못한다
금지 근거 코드 차단  기억이 아니라 시스템이 거부한다
정의서 착수 Gate    근거 없이 코드를 시작할 수 없다
RAW 무손실          틀려도 다시 읽어 고칠 수 있다
```

## 용어

| 용어 | 뜻 |
|---|---|
| RAW | 사이트가 준 원문. 손대지 않고 저장. 삭제 금지 |
| CORE | 사이트 무관 공통 스키마. 파싱 결과 |
| 축 (axis) | 점수를 매기는 단위. 가격 · 보증 · 사양 등 |
| 판정 (verdict) | 축의 값 + 그 값을 정한 근거 + 우선순위 |
| 근거 우선순위 | 제조사 사양 > 매물 실측 > 판정기 > 문자열 추정 |
| `-1` | 그 차종에 애초에 없는 사양. 분모에서 제외 |
| facet | 목록 API 가 주는 집계. **사전용이지 판정 근거가 아니다** |
| 정의서 | 스텝 착수 전 제출하는 명세. Gate 6개를 통과해야 코드 시작 |
