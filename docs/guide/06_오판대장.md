# 2. 되풀이되는 모양 넷

## ② 데이터가 되는지 안 보고 식을 만든다 — 11

```
마스터가 「옵션·트림 값이 중요하다」 하시니 그럴듯한 계산식으로 답했다
★ 같은 조건에서 옵션만 다른 매물이 몇 쌍인지 세지 않았다
막을 것   ★ 식을 내기 전에 표본 수를 먼저 센다
```

## ③ 조건을 맞추려고 기준을 흔든다 — 12·13·14

```
「보증 없으면 A 가 안 된다」를 풀려고
  분모를 줄였다 → 등급이 등급이 아니게 된다
  분위로 바꿨다 → 볼 필요 없는 것까지 등급을 받는다
  순위로 바꿨다 → 같은 잘못
★ 실제 답은 「배점 비율만 고치는 것」이었다 (개정 424)
막을 것   ★ 컷 · 분모 · 총점은 마스터가 정하신 것이다.  가이드가 안 만진다
```

## ⑥ 내가 만든 규격을 내가 잊는다 — 20·21

```
개정 292 「취향은 등급에서 뺀다」를 내가 썼는데
★ 개정 424·428 에서 취향을 95 → 145 로 크게 올리며 그것을 잊었다
★ 그래서 분모 675 로 검산했고 실제는 599 였다
★ recalc 결과 A 이상 0건.  「검증만 있어도 A」가 애초에 불가능했다
배점이 두 곳(components · axis_rules)에 있는 것도 안 봤다
막을 것   ★ 배점·분모를 바꾸기 전에 ★ 지금 코드가 무엇으로 나누는지 먼저 센다
         ★ 시뮬 전에 실제 config 값을 읽어 온다.  손으로 지어내지 않는다
```

## ⑤ 남의 조사 결과를 검증 없이 받아 적는다 — 17·18

```
개발측이 「원문에 틴팅 0건」이라 하자 그대로 규격에 적었다
★ 마스터가 캡처 한 장으로 뒤집으셨다
★ 개발측이 뒤진 곳이 맞는 곳인지 내가 안 봤다 —
  「엔카진단 리포트」는 별도 엔드포인트일 수 있는데 그 가능성을 안 물었다
막을 것   ★ 「없다」는 답을 받으면 ★ 어디를 뒤졌는지를 함께 본다
         ★ 화면에 보이는데 원문에 없으면 「안 받은 것」을 먼저 의심한다
```

## ④ 적은 표본으로 결론을 낸다 — 10·16
