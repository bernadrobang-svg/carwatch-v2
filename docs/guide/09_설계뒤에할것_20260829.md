
**0a-2 넣기는 「다 넣기」가 아니다** — 목록과 DB 를 대본다.
목록에 있고 DB 에 없다 → 새로 넣는다 · 값이 다르다 → **그 칸만** 고친다 ·
**값이 같다 → 아무것도 안 한다**(지금은 매번 `upsert_core` 를 부른다) ·
DB 에 있는데 목록에 없다 → **상태를 바꾼다**.
**상태는 `sales_status` 에 사이트가 준 말 그대로** — 「계약 중·판매 완료·삭제」가 지금 `gone` 하나로 뭉친다.

**1걸음 · 받기 — 파일만 쓴다. DB 를 안 연다.**
```
raw/{site}/{endpoint}/{YYYY-MM-DD}/{source_id}.json   매물번호가 있는 것
raw/{site}/{endpoint}/{YYYY-MM-DD}/page-{NNNN}.json   목록처럼 번호가 없는 것
뿌리는 config/deploy.json 의 work_dir 아래 raw/ — 코드에 박지 마라
한 파일 = {"site","endpoint","source_id","url","status","fetched_at","body"}
body 는 원문 그대로.  자르지 않는다 (P3 무손실).  HTML 도 이 껍데기에 담는다
site 는 config/sites.json 키 · endpoint 는 endpoints.json 키 (list·detail·inspection·stock_list)
```
**2걸음 · 넣기 — 그 폴더를 읽어 `raw_response` ＋ `core_listing` 에 넣는다.** 통신이 없다.
이미 넣은 파일은 건너뛴다(`fetched_at` vs `parsed_at`). 파일을 지우지 마라.
**둘을 따로 돌릴 수 있게 만들어 달라** — 받기만, 넣기만.
