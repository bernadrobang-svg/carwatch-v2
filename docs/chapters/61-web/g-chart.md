# ★★★ 미분류는 원인을 갈라서 낸다 — 08-18

**마스터 지적 — 「미분류는 왜 있는 거야. 원인 분석 안 해?」**

## 지금

```
화면   「등록부 미분류 349건 — V4-11 이 판정을 막는다」
★ 349 라는 숫자만 있고 무엇인지 없습니다
★ 「무엇을 하면 되나」에 「config 를 확인·수정해 옮긴 뒤 재실행한다」만 있습니다
  ★ 349개를 사람이 하나씩 보라는 뜻입니다
```

## 규격

```
필수   미분류를 원인별로 가른다
       ① 새 엔드포인트에서 온 새 필드      ← 받은 게 늘면 늡니다
       ② 같은 뜻인데 이름이 다른 것        ← 자동으로 이을 수 있습니다
       ③ 값이 늘 비어 있는 것             ← 안 쓰기로 정하면 됩니다
       ④ 정말 새로운 것                   ← 사람이 봐야 합니다

필수   ①②③ 을 자동으로 처리할 규칙을 만든다
       ② 이름이 다른 것   기존 필드와 값 분포가 같으면 이어 준다
                        ★ 사람에게 「같은 것으로 보입니다」를 제안한다
       ③ 늘 비어 있는 것  전건 null 이면 「안 씀」으로 제안한다
필수   ④ 만 사람에게 남긴다.  숫자를 함께 낸다
       「사람이 봐야 할 것 12개 · 나머지 337개는 제안이 있습니다」

필수   엔드포인트별로 낸다
       「record/summary 에서 온 새 필드 84개」
       ★ 어디서 왔는지 알면 왜 늘었는지 압니다
필수   ★ 각 필드가 몇 건에서 관측됐는지 낸다
       ★ 3,528건 전부에 있는 필드와 1건짜리는 급한 정도가 다릅니다
필수   자주 나온 순으로 정렬한다
금지   「349건 미분류」라고만 내는 것
검산   V4-26  미분류가 원인별로 갈려 있는가
       V4-27  자동 제안이 있는 것과 사람이 봐야 하는 것이 갈려 있는가
```
