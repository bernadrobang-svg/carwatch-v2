### ★ 축 총점 변경 — 비율 재배분과 정수 보정

```
예   warranty 100 → 120
    general 50 · power 50  →  60 · 60      나누어떨어진다

예   spec 90 → 100
    hud 20 · sunroof 20 · svm 10 · scc 10 · bsd 5 · tinting 5
    × 100/90 = 22.22 · 22.22 · 22.22 · 11.11 · 11.11 · 5.56 · 5.56
```

**반올림하면 합이 안 맞는다. 잔여를 최대 성분에 몰아준다.**

```
1  각 성분 = round(기존 × 새 총점 ÷ 기존 총점)
2  잔여 = 새 총점 − Σ(반올림 결과)
3  잔여를 배점이 가장 큰 성분에 더한다.  같으면 이름 순 첫 번째
4  Σ components == total_points 를 저장 전에 검산한다
```

```
결과   22 · 22 · 22 · 11 · 11 · 6 · 6 = 100      (반올림 합 100.  잔여 0)
★ 0 이 되는 성분이 생기면 거부한다
  「점수가 0인 성분」과 「스킵한 성분」은 다르다.  스킵을 쓰라고 안내한다
```

### 성분 추가 · 스킵

```
추가   선택 가능 목록에서만 고른다.  임의 입력을 받지 않는다
       목록 = ListingSnapshot 에 필드가 있고 판정 함수가 있는 것 (STEP 129)
스킵   components 에서 빼지 않는다.  skipped: true 로 표시한다
       빼면 「있었는데 뺐다」가 기록되지 않는다
효과   스킵된 성분은 총점 계산에서 제외.  분모에도 안 들어간다
       excluded 와 다르다 — excluded 는 그 매물만, 스킵은 전 매물이다
```


## STEP 129 [규격] — 성분 선택 가능 목록

```
목적    관리자가 없는 성분을 만들지 못하게 한다
원천    ListingSnapshot 필드 · analyze/axis/ 판정 함수 · meta_field_usage
입력    없음 (시스템이 산출)
출력    선택 가능 성분 목록 + 각각의 상태
값규칙  세 조건을 모두 만족해야 「선택 가능」이다
근거    데이터가 없거나 판정 함수가 없으면 그 성분은 항상 NULL 이다
금지    임의 문자열로 성분을 추가하는 것
검산    선택 가능 목록의 성분이 전부 판정 결과를 내는가
```

| 조건 | 확인 |
|---|---|
| DTO 필드 존재 | `ListingSnapshot` 에 그 값이 있는가 |
| 판정 함수 존재 | `analyze/axis/` 에 해당 로직이 있는가 |
| 등록부 상태 | `meta_field_usage.usage = 'in_use'` 인가 |

```
표시   선택 가능      셋 다 만족
      데이터 없음    등록부가 blocked · not_provided → 사유 표시
      함수 없음      개발 요청 버튼 (STEP 137)
```

```
★ 「함수 없음」이 개발 요청의 주된 입구다
  관리자가 「이 필드로 점수를 매기고 싶다」를 말하는 자리다
```
