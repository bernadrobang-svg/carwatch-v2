## STEP 133 [규격] — 조회 전용 쿼리

```
목적    관리자가 DB 를 직접 조회한다
원천    사용자 입력 SQL
입력    SQL 문자열
출력    결과 표 + 복사 버튼 · CSV·JSON 내보내기
값규칙  SELECT 만 허용한다.  그 외는 거부하고 사유를 낸다
근거    변경이 가능하면 RAW 무손실(P3)이 깨진다
       원문을 지우면 재파싱으로 복구가 안 된다
금지    문자열 필터로 판정하는 것.  주석·부분 문자열로 우회된다
검산    거부 목록의 쿼리가 전건 거부되는가
```

### 판정 방식 — 컴파일해서 본다

```
방식   sqlite3 가 SQL 을 컴파일하고, 바이트코드에 쓰기 연산이 있으면 거부
근거   문자열 필터는 주석 · 부분 문자열 · 다중 문장으로 우회된다
      파서가 아니라 실행 엔진이 판정하므로 우회할 여지가 없다
```

```
허용   SELECT · WITH · 서브쿼리 · JOIN · 집계
거부   INSERT · UPDATE · DELETE · DROP · ALTER · CREATE · REPLACE
      PRAGMA · ATTACH · 다중 문장
```

**거부 표본을 시험에 고정한다.**

```
SELECT 1; DELETE FROM …            다중 문장
-- 주석 뒤 DELETE FROM …            줄 주석 우회
/* c */ UPDATE account SET role=…  블록 주석 우회
```

```
필수   거부된 것도 QueryLog 에 남긴다.  무엇을 시도했는지가 기록이다
```

```
★ 「업데이트가 필요하면 개발 요청으로」 — 마스터 확정
  쿼리로 데이터를 고치지 않는다.  고칠 일이 있으면 그 자체가 결함이다
  거부 화면에 개발 요청 버튼을 둔다 (STEP 137)
```

### 제한

```
행 수      config.admin.query_row_limit
실행 시간   config.admin.query_timeout_sec
raw_* body  길이만 표시.  전문은 별도 버튼 (한 건씩)
감사       QueryLog 에 전건 기록.  거부된 것도 남긴다
```

```
필수   결과를 그대로 복사할 수 있게 한다 (탭 구분 · CSV · JSON)
★ 복사한 수치를 문서에 넣지 않는다 (0장 STEP 5.5)
  분석 근거로 쓰되, 지시서 본문에는 규칙만 남긴다
```

## STEP 137 [규격] — 개발 요청

```
목적    없는 기능 · 막힌 것을 기록해 세션에 전달한다
원천    관리자 입력 + 발생 맥락 자동 수집
입력    title · body · origin · context
출력    DevRequest 1행
값규칙  status 8종 밖의 값을 받지 않는다
근거    「지금 안 되는 것」이 기록되지 않으면 다음 세션이 모른다
금지    요청을 삭제하는 것.  상태 전이로만 관리한다
검산    내보낸 요청이 전건 exported_at 을 갖는가
```

### 상태 8종

```
draft        작성 중
requested    내보내기 완료.  세션에 전달됨
in_progress  세션에서 검토 중
applied      지시서 반영 + 구현 완료
not_applied  검토 후 반영하지 않기로.  사유 필수
misapplied   반영됐으나 의도와 다름.  재요청 대상
reopened     applied 였으나 다시 문제.  재개
```

```
전이   draft → requested → in_progress → applied · not_applied
      applied → misapplied → reopened → in_progress
      not_applied → reopened  (마스터가 다시 요청)
필수   applied · not_applied · misapplied 는 사유(direction)를 받는다
필수   applied 는 step_ref 를 받는다.  어느 STEP 에 반영됐는가
```

### 요청이 생기는 자리

```
성분 추가 화면    「함수 없음」인 필드 (STEP 129)
쿼리 화면        UPDATE 거부 시 (STEP 133)
등록부           blocked 항목의 해소 요청 (STEP 87)
화면 어디서나     「이 기능이 없다」 버튼
```

```
자동 수집 맥락   발생 화면 · 시도한 값 · 관련 STEP · 그때의 VersionStamp
근거           「무엇을 하려다 막혔는가」가 없으면 세션이 판단할 수 없다
```

### 내보내기

```
형식   md.  개정 이력과 같은 표 형태
내용   status 별로 묶어서.  requested 와 reopened 를 먼저
파일   dev_requests_{날짜}.md
```

```
★ 세션이 이 파일을 읽고 지시서를 고친다
  고친 뒤 step_ref 를 채워 돌려준다.  관리자가 applied 로 표시한다
반영 확인   지시서 개정 이력에 그 STEP 이 있는가로 대조한다
```
