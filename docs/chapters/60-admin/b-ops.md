## STEP 132a [규격] — 큐를 가져가는 실행기 ★ 08-16

```
목적    큐에 넣은 작업이 실제로 돈다
근거    실측 08-16.  run.py 가 recalc_job 을 한 번도 읽지 않는다
       넣기만 하고 아무도 안 가져가서 queued 가 쌓이고
       JOB_OPEN=("queued","running") 때문에 관리 화면 전체가 409 로 잠겼다
       두 번 겪었다
```

```
필수   큐에 넣은 것은 누군가 가져간다.  실행기가 있어야 한다
필수   실행기가 없으면 큐에 넣지 않는다 — 바로 돌리거나 거절한다
필수   화면 문구가 사실이어야 한다
       실행기가 없으면서 「자동으로 돕니다」라 적지 않는다
필수   queued 가 일정 시간 넘게 남으면 화면이 그것을 알린다
       「N분째 대기 중 — 실행기가 도는지 확인하십시오」
금지   큐가 밀렸다는 이유로 관리 화면 전체가 잠기는 것
       조정만 잠근다.  운영·탐색은 열어 둔다 (STEP 149j)
검산   V10-22  queued 를 소비하는 코드가 있는가
       V10-23  오래된 queued 가 화면에 표시되는가
```

```
★ 지금 선택지 두 가지
  A. 실행기를 만든다 — systemd 타이머가 주기적으로 큐를 가져간다
  B. 큐를 안 쓴다 — 화면이 바로 돌리고 진행을 표시한다
  B 가 1인 도구에 맞다.  큐는 여럿이 쓸 때 필요하다
```
