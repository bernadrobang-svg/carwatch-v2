## STEP 70 — 가격 · 기대가와 감가 곡선

```
version  SPEC-2026.09.02-r1063
follows  ★ 정본 — 배점의 원천은 `config/scoring.json`
sources  실측 08-22
checks   S46-38 · S46-39
```


### 목적

```
같은 차종·같은 연식에서 이 매물이 시세보다 싼가 비싼가를 판정한다.
절대 가격이 아니라 「기대가 대비」로 본다.
```

### 기대가

```
기대가 = 신차가 × 감가계수(경과월) × 차종 보정계수
```

| 요소 | 원천 | 비고 |
|---|---|---|
| 신차가 | `category.originPrice` × 10,000 | **만원 단위.** 옵션 미포함 기본가일 수 있음 |
| 경과월 | `year_month` 기준 | `first_registration_date` 가 있으면 우선 |
| 감가계수 | 아래 실측 곡선 | |
| 보정계수 | 차종별 자동 산출 (6장 STEP 64) | |

### ★ 감가 곡선 — 손으로 적지 않는다

```
v1 사고   87 / 69 / 55% 를 코드에 박았다.  출처가 없었다
         가격 축 전체가 그 위에 얹혀 있었고, 실측과 어긋났다
```

**곡선은 수집 결과에서 산출한다.**

```sql
SELECT CAST(age_months/12 AS INT) yr, COUNT(*),
       AVG(CAST(price_current_won AS REAL)/price_origin_won)
  FROM core_listing
 WHERE price_origin_won>0 AND price_current_won>0 AND age_months IS NOT NULL
 GROUP BY 1;
```

```
저장   config/depreciation.json.  첫 수집 후 생성하고 주기적으로 갱신한다
금지   곡선 값을 코드에 상수로 두는 것 (6장 V4-13)
```

### ★ 표본 부족 시 — 지어내지 않는다

```
값규칙   전 사이트 유효 표본이 config.depreciation.curve_min_sample 미만이면
        곡선을 산출하지 않는다.  기저 기대가 = NULL
        → 가격 축 NULL + excluded (STEP 71 과 같은 처리)
        → 화면 「감가 곡선 미산출 — 가격 평가 불가」

금지    곡선 값을 사람이 적어 넣는 것
       표본이 없는 연차를 인접 연차로 보간해 채우는 것

근거    곡선은 사이트 공통이라 전 매물이 모수다.  표본 부족은 사실상 발생하지 않는다
       발생한다면 수집 실패 신호이지 곡선을 지어낼 이유가 아니다
```

**연차별로 갈리는 경우가 실제 문제다.**

```
그 연차만 NULL 로 두고, 해당 연차 매물의 가격 축을 excluded 한다
보간은 추정이라 금지다
```

### 이 곡선의 한계 — 반드시 명시한다

```
① 호가다.  실거래가가 아니다
② originPrice 가 그 매물의 실제 신차가가 아닐 수 있다 (옵션 미포함 기본가)
③ 차종별 편차가 크다.  단일 곡선을 그대로 쓰면 안 된다
```

**v1 에서 실제로 나온 이상 2종**

```
잔가율 1.0 초과      신차가보다 비싸게 나온 차종이 있었다
                   originPrice 가 기본 트림가일 가능성
연차 역전            4년보다 5년 잔가율이 높게 나온 차종이 있었다
                   표본 부족 또는 originPrice 부정확
→ 산출 후 이 두 패턴을 반드시 검사한다 (6장 V5-06)
```

### ★ 계수가 가드에 걸리면 어떻게 하는가

```
사례   스포티지 LPi 계수 1.517.  coefficient_sane_range [0.80, 1.20] 밖
원인   originPrice 중앙값이 실매물 중앙값보다 낮다
      기본 트림가가 들어가 있어 옵션·상위 트림 가격을 반영하지 못한다
```

| 조치 | 판정 |
|---|---|
| 계수를 그대로 쓴다 | **금지.** 그 차종만 기대가가 1.5배가 된다 |
| 범위 안으로 자른다 | **금지.** 근거 없이 값을 만드는 것이다 |
| **그 차종의 가격 축을 `excluded`** | **채택** |

```
동작   계수가 sane_range 밖  →  그 target 의 price 축을 NULL + excluded
      다른 축은 정상 판정한다.  분모만 200 줄어든다
표시   「신차가 정보가 부정확해 가격 평가를 하지 않았습니다」
기록   coefficient_history 에 사유와 함께 남긴다
해소   originPrice 를 트림별로 받는 경로를 찾거나, 유사군(82e) 으로 대체
```

**추정으로 채우지 않는다는 원칙이 계수에도 적용된다.**

**따라서 감가 곡선은 전 차종 공통 기준선으로만 쓰고, 차종별 보정계수가 실제 조정을 한다.**

```
검증   보정계수가 config.depreciation.coefficient_sane_range 밖이면 그 차종의 originPrice 를 의심한다
      초기값은 config 에 둔다
      스포티지는 착수 시 반드시 확인 대상이다 (STEP 86)
```

### 함수

```
analyze_price
목적      기대가 대비 위치를 점수화
입력      current_price · origin_price · age_months · target_key
출력      price 축 값(구간) · source
사용 필드  ListingSnapshot.price_current_won · price_origin_won · year_month
근거      위 실측 잔가율 + 차종 보정계수
금지      보증 잔여 가치를 가격에서 차감하는 것 (보증 축과 이중 계산)
NULL      origin_price 없음 → 축 NULL (분모 제외).  0 이 아니다
검산      기대가 ÷ 실매물 중앙값 이 1.0 ± 0.1
```

## STEP 71 [판정] — 가격 · 배점 곡선

```
목적    기대가 대비 위치를 점수로 바꾼다
원천    STEP 70 의 기대가 · price_current_won
값규칙  기대가가 NULL 이면 (originPrice 부재) 가격 축 NULL + excluded.  0 점이 아니다
근거    기대가는 「평균적인 매물 값」이다.  딱 맞으면 중간 점수가 맞다
금지    보증 잔여 가치를 가격에서 차감하는 것 (STEP 83)
검산    구간별 건수가 ±0% 에 최빈값을 갖는 종 모양인가.  쏠리면 계수가 틀렸다
```

**기대가와 같으면 ★ 그 축 만점의 절반을 준다. 위아래로 뻗는다.**

| 기대가 대비 | 점수 |
|---|---:|
| −25% 이하 | 200 |
| −20% | 180 |
| −15% | 160 |
| −10% | 140 |
| −5% | 120 |
| **±0%** | **100** |
| +5% | 70 |
| +10% | 40 |
| +15% | 10 |
| +25% | −40 |
| 초과 | −100 |

### 근거

```
기대가는 「평균적인 매물 값」이다.  딱 맞으면 중간 점수가 맞다
v1 초판은 ±0% 에 60점(30%)을 줘서 매물 74% 가 하위 구간에 몰렸다
       → 가격 축 평균이 만점의 30%.  변별이 안 됐다
```

**음수 구간을 두는 이유** — 시세보다 비싼 매물은 다른 축이 좋아도 사면 안 된다.
**0 으로 막으면 「비싸도 손해는 없는」 것이 된다.**

```
검산   구간별 건수가 중앙(±0%)에 최빈값을 갖는 종 모양이어야 한다
      한쪽으로 쏠리면 보정계수가 틀린 것이다
실측   콜레오스 208건 — ±0% 74건 · +5% 77건 · −25% 15건
```

## STEP 72 — 보증  ★ 배점은 `f-table` 5장-2a

### 목적

```
잔여 보증은 향후 수리비 리스크를 직접 줄인다.
금액으로 환산 가능한 유일한 축이다.
```

### 구성

```
일반보증 50 + 파워트레인 50
```

| 항목 | 원천 |
|---|---|
| 일반 | `category.warranty.bodyMonth` · `bodyMileage` |
| 파워트레인 | `warranty.transmissionMonth` · `transmissionMileage` |
| 경과 기준 | `first_registration_date` (점검부) → 없으면 `year_month` |

### 산식

```
잔여개월 = min( 보증월 − 경과월 ,  (보증km − 주행km) ÷ 1,250 )
점수     = min(잔여개월, 24) ÷ 24 × 50
```

| 상태 | 점수 |
|---|---:|
| 잔여 24개월 이상 | 50 |
| 0~24 | 선형 |
| 만료 1축 | −15 |
| 양축 만료 | 합계 −30 |
| NULL | 0 |

### 근거

```
만점 24개월    2년 이상 남으면 그 사이 발생할 주요 고장이 무상 처리된다
              실측 분포에서 12~36개월이 대부분이라 변별이 되는 구간
월 1,250km    연 15,000km.  국내 승용 평균
음수 허용      하한 0 으로 자르면 만료 페널티가 걸리지 않는다
−15 / −30     축 만점의 25% 페널티(v1 초안)는 다른 축을 덮어 등급을 뒤집는다
```

### 전기차 — 파워트레인은 배터리다

```
실측   모델Y  transmissionMonth · transmissionMileage 가 전건 동일하고
      테슬라 배터리 보증(8년 / 19.2만km)과 정확히 일치한다
→ 필드명이 '변속기' 일 뿐 값은 배터리 보증이다.  그대로 쓴다
```

```
근거 우선순위   1 엔카 실측(transmissionMonth) > 2 배터리 전용 필드 > 3 차종 설정표
기록          warranty_source 에 encar · battery · config 중 무엇인지 남긴다
★ 미확정      제네시스 전동화 3종(GV60·GV70_EV·G80_EV)의 transmissionMonth 미확인 (STEP 86)
```

### 표시 전용 — 점수에 반영하지 않는다

```
extendWarranty          엔카 유료 연장보증 가입
deemedExtendWarranty    제조사 보증 잔여로 동등 간주
```

**`deemedExtendWarranty` 로 안전 축에서 또 받으면 같은 사실로 두 번 우대한다.**

```
검산   차종 평균이 85 를 넘으면 변별력 경고.  연식이 좁은 차종에서 발생
실측   G80 50 · 콜레오스 81 · 모델Y 81
```
