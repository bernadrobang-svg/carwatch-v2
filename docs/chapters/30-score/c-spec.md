## STEP 73 [판정] — 사양 90점 · 축 구성

```
목적    마스터가 필요로 하는 사양이 달려 있는가를 본다
원천    options.standard(3자리) · options.choice(4~5자리) · contents.text · 제조사 사양표
값규칙  Component 단위로 1/0/NULL/-1.  excluded 는 분모에서 뺀다 (STEP 83)
근거    HUD·HDA·선루프는 마스터가 대체 불가로 지정했다.  동일 가중
금지    카탈로그 전체 목록 · facet Count 를 장착 근거로 쓰는 것
검산    Component 별 값 종류가 1이면 그 축은 순위에 기여하지 않는다 (V3-04)
```

### 목적

```
마스터가 필요로 하는 사양이 달려 있는가.
차종이 제공하지 않는 사양으로 감점하지 않는다.
```

| 축 | 배점 | 값 | 근거 |
|---|---:|---|---|
| HUD | 20 | 1/0/NULL/−1 | 마스터 필수 스펙 |
| **HDA** | **20** | **2/1/0/−1** | 마스터 필수. 3단계 (STEP 75) |
| 선루프 | 20 | 1/0/NULL/−1 | 마스터 선호 |
| SVM | 10 | 1/0/NULL/−1 | 주차 편의 |
| SCC | 10 | 1/0/NULL/−1 | HDA ≥ 1 이면 자동 충족 |
| 후측방 | 5 | 1/0/NULL/−1 | 안전 보조 |
| 틴팅 | 5 | 1/0/NULL | 인수 후 비용 |
| **합** | **90** | | |

```
사양 점수 = (획득 ÷ 적용 가능 배점) × 90
적용 가능 배점 = 90 − Σ(excluded=True 인 축의 배점)
```

### 배점 근거

```
HUD 20 · HDA 20 · 선루프 20   마스터가 대체 불가로 지정한 3개.  동일 가중
SVM 10 · SCC 10              편의.  없어도 운행에 지장 없음
후측방 5                     대부분 기본 장착이라 변별력 낮음
틴팅 5                       불명이 다수 예상.  낮게
```

**HDA 가 HUD 와 같은 20점인 이유** — 마스터가 테슬라 Autopilot 을 HDA 상위로 지정했고,
**주행 보조는 장거리 운행에서 HUD 보다 실효가 크다는 판단이다.**

## STEP 74 [판정] — 사양 · 근거 우선순위와 `−1`

```
목적    같은 축에 여러 근거가 오면 무엇이 이기는지 고정한다
원천    SPEC_DEFAULT_ON · options.standard/choice · 전용 판정기 · contents.text
값규칙  -1 은 제조사 사양표 근거로만 붙인다.  facet Count 0 은 근거가 아니다
근거    사양표 > 실측 > 판정기 > 문자열.  뒤로 갈수록 틀릴 여지가 크다
금지    put() 을 거치지 않고 값을 직접 대입하는 것
검산    source 분포가 전건 keyword 면 1·2순위 경로가 죽어 있는 것이다 (V3-03)
```

### 우선순위

```
1  제조사 사양표      SPEC_DEFAULT_ON / SPEC_DEFAULT_OFF   차종별 명시 등록
2  실장착 옵션        options.standard(3자리) + options.choice(4~5자리)
                    + 그 코드의 이름 (카탈로그 사전 조회)
3  전용 판정기        classify_hud · classify_hda · classify_tinting
4  키워드            contents.text · 트림명
금지 카탈로그 전체목록 · facet Count
```

```
1 이 2 를 이긴다   사양표상 전 트림 기본이면 choice 에 없어도 1
2 가 4 를 이긴다   판매글에 「선루프」가 있어도 실장착에 없으면 0
```

**v1 실사고** — 판매글 키워드가 실장착을 이겨 선루프 84건이 부당하게 1이었다.

### 카탈로그 — 사전이냐 근거냐

```
허용   그 매물의 options.choice 코드 → 이름 조회
      installed_option_names(codes, model_catalog_key)
      codes 는 그 매물 것만.  빈 codes 에 빈 목록을 반환해야 한다
금지   /options/choice 가 반환한 전체 목록을 장착으로 취급
      → 그 모델이 파는 옵션이면 전 매물이 '있음' 이 된다
```

### `−1` 등록 — 명시 등록만

```
근거   제조사 공식 사양표상 그 차종 전 트림 미제공
금지   facet Count 0 · JatoOptions Count 0 · 자동 판정
```

| 차종 | 축 | 근거 |
|---|---|---|
| 모델Y | HUD | 테슬라 전 트림 미제공. facet Count 13 은 딜러 오체크 |

```
실측 근거   모델Y 어댑티브 크루즈 — Autopilot 이 전 차량 기본인데 미체크가 다수
           모델Y HUD — 테슬라에 없는 옵션인데 오체크가 존재
→ facet 은 딜러 체크값이라 양방향으로 틀린다.  -1 근거로 쓸 수 없다
```

## STEP 75 — 사양 · HDA 3단계와 틴팅

### HDA 3단계

| 값 | 배점 | 해당 |
|:---:|---:|---|
| 2 | 20 | 테슬라 Autopilot/FSD · HDA2 · G80 2022 `1044` |
| 1 | 12 | HDA · 르노 액티브 드라이버 어시스트 |
| 0 | 0 | SCC 만 |
| −1 | 분모 제외 | 차종 미제공 |

```
근거   자동 차선변경·분기로 진입이 가능한 것과 차로 유지만 되는 것은 실효가 다르다
      마스터가 Autopilot 을 HDA 상위로 확정했다
1단계 12점   20점의 60%.  「있긴 하다」와 「상위다」의 차이를 8점으로 표현
```

**별도 축을 세우지 않는다.** 테슬라만 받는 가점 축은 다른 후보를 구조적으로 불리하게 만든다.

### ★ Gate 확정 — `description` 실측으로 열렸다 (2026-08-11)

| `optionName` | `description` 에 「고속도로 주행 보조」 | 판정 |
|---|:--:|---|
| 드라이빙 어시스턴스 패키지 **II** | **있음** — 「고속도로 주행 보조 2」 | **HDA 2** |
| 현대 스마트센스 **II** | **있음** — 「고속도로 주행 보조 2」 | **HDA 2** |
| 드라이브 와이즈 | **있음** — 「고속도로 주행 보조 2」 | **HDA 2** |
| 드라이빙 어시스턴스 패키지 **Ⅰ** | 없음 — 서라운드 뷰 · 후측방 모니터 | HDA 아님 |
| 드라이빙 어시스턴스 패키지 (숫자 없음) | 없음 — 서라운드 뷰 · 빌트인 캠 | HDA 아님 |
| 현대 스마트센스 **I** | 없음 — 후측방 충돌 경고 | HDA 아님 |

```
★ 「Ⅰ」과 「II」가 로마숫자(U+2160)와 라틴 대문자로 섞여 온다
필수   판정 근거는 description 의 문구다.  옵션명의 Ⅰ·II 로 가르지 않는다
필수   2 문구를 먼저 본다.  1 문구가 2 문구에 포함된다
설정   config.scoring.axis_rules.spec.hda_level2_phrases
      ["고속도로 주행 보조 2", "고속도로 주행보조 2", "HDA 2"]
      hda_level1_phrases  ["고속도로 주행 보조", "고속도로 주행보조", "HDA"]
검산   V3-33  HDA 판정이 전건 description 근거인가
excluded  카탈로그를 못 받은 매물만.  Gate 미통과가 아니다
```

### ★ 판정 근거 — 옵션명이 아니라 `description` 이다 (2026-08-09 원문 정정)

**v1 문서의 「1044 = 고속도로 주행 보조 2」는 근거가 없었다.**
**카탈로그에 그런 옵션명은 존재하지 않는다. 실제 옵션명은 「드라이빙 어시스턴스 패키지」다.**

```
실측 — option_catalog

1044  드라이빙 어시스턴스 패키지 II
      description: 전방 충돌방지 보조(...), 스마트 크루즈 컨트롤(운전 스타일 연동),
                   내비게이션 기반 스마트 크루즈 컨트롤(진출입로),
                   고속도로 주행 보조 2(차로 변경 보조 제어 기능 포함),
                   앞좌석 프리액티브 시트벨트

1043  드라이빙 어시스턴스 패키지 Ⅰ
      description: 서라운드 뷰 모니터, 증강현실 내비게이션, 후측방 모니터,
                   원격 스마트 주차 보조, 후방 주차 충돌방지 보조
```

**Ⅰ 에는 HDA 가 없다. II 에만 있다.**
**옵션명의 「Ⅰ / II」로 판단하면 안 된다. `description` 을 본다.**

```
판정 근거 (우선순위 순)
  1  SPEC_DEFAULT_ON 등록 차종        모델Y = 2 (Autopilot)
  2  description 에 "고속도로 주행 보조 2"          →  2
  3  description 에 "고속도로 주행 보조"            →  1
  4  description 에 HDA 문구 없음 · SCC 만 있음     →  0
```

```
실측   description 에 "고속도로 주행 보조" 포함 옵션 78건
      옵션명은 제각각이다 — 드라이빙 어시스턴스 패키지 II · 파퓰러 패키지Ⅱ
                          프레스티지 패키지 · 현대 스마트센스 II · 드라이브 와이즈
                          12.3인치 내비게이션
→ 옵션명 목록을 손으로 적는 방식은 반드시 누락된다.  description 검색이 맞다
```

### ★ 착수 Gate — HDA 는 실측 확정 전 코드에 넣지 않는다

```
[ ] "고속도로 주행 보조" · "고속도로 주행 보조 2" 의 표기 변형을 전수 확인
    (숫자 2 · Ⅱ · II · 공백 유무)
[ ] 78건 전량의 option_name · description 을 사전에 등록
[ ] 2 와 1 로 갈리는 경계 사례 표본 제출
[ ] 모델Y SPEC_DEFAULT_ON 근거 문서화
```

**Gate 통과 전에는 `hda` 축을 NULL + `excluded=True` 로 둔다.**
**추정으로 1 이나 2 를 매기지 않는다.**
