## STEP 74 [판정] — 사양 · 근거 우선순위와 `−1`

```
목적    같은 축에 여러 근거가 오면 무엇이 이기는지 고정한다
원천    SPEC_DEFAULT_ON · options.standard/choice · 전용 판정기 · contents.text
값규칙  -1 은 제조사 사양표 근거로만 붙인다.  facet Count 0 은 근거가 아니다
근거    사양표 > 실측 > 판정기 > 문자열.  뒤로 갈수록 틀릴 여지가 크다
금지    put() 을 거치지 않고 값을 직접 대입하는 것
검산    source 분포가 전건 keyword 면 1·2순위 경로가 죽어 있는 것이다 (V3-03)
```

### 우선순위

```
1  제조사 사양표      SPEC_DEFAULT_ON / SPEC_DEFAULT_OFF   차종별 명시 등록
2  실장착 옵션        options.standard(3자리) + options.choice(4~5자리)
                    + 그 코드의 이름 (카탈로그 사전 조회)
3  전용 판정기        classify_hud · classify_tinting
4  키워드            contents.text · 트림명
금지 카탈로그 전체목록 · facet Count
```

```
1 이 2 를 이긴다   사양표상 전 트림 기본이면 choice 에 없어도 1
2 가 4 를 이긴다   판매글에 「선루프」가 있어도 실장착에 없으면 0
```

**v1 실사고** — 판매글 키워드가 실장착을 이겨 선루프 84건이 부당하게 1이었다.

### 카탈로그 — 사전이냐 근거냐

```
허용   그 매물의 options.choice 코드 → 이름 조회
      installed_option_names(codes, model_catalog_key)
      codes 는 그 매물 것만.  빈 codes 에 빈 목록을 반환해야 한다
금지   /options/choice 가 반환한 전체 목록을 장착으로 취급
      → 그 모델이 파는 옵션이면 전 매물이 '있음' 이 된다
```

### `−1` 등록 — 명시 등록만

```
근거   제조사 공식 사양표상 그 차종 전 트림 미제공
금지   facet Count 0 · JatoOptions Count 0 · 자동 판정
```

| 차종 | 축 | 근거 |
|---|---|---|
| 모델Y | HUD | 테슬라 전 트림 미제공. facet Count 13 은 딜러 오체크 |

```
실측 근거   모델Y 어댑티브 크루즈 — Autopilot 이 전 차량 기본인데 미체크가 다수
           모델Y HUD — 테슬라에 없는 옵션인데 오체크가 존재
→ facet 은 딜러 체크값이라 양방향으로 틀린다.  -1 근거로 쓸 수 없다
```
