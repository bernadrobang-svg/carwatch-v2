```
목적    총점을 등급으로 바꿔 비교 가능하게 한다
원천    result_score.score_total · denominator · absolute_fail
값규칙  분모 미달은 NOT_RATED.  D 나 E 가 아니다.  순위도 매기지 않는다
근거    비율 기준(90/80/70/60%)이라 총점이 바뀌어도 등급 의미가 유지된다
금지    버전이 다른 결과를 한 목록에 섞어 정렬하는 것
검산    S~C 가 0건이고 D·E 만 있으면 축이 안 붙는 것이다 (V5-05)
```

### ★ 등급은 비율로 판정한다 — 절대점수가 아니다

```python
ratio = earned / denominator          # ★ 08-14 정정.  earned 는 실제 획득분이다

★ score_total 로 나누지 않는다
  score_total = earned / denominator × total_points  — 이미 총점으로 환산된 값이다
  그것을 다시 denominator 로 나누면 555/denominator 배 부풀려진다
  실측 08-14   earned 245 / denom 455 = 53.8% (D)
              score_total 298.85 / 455 = 65.7% (C)   ← 한 등급 위로 올라간다
  분모가 작을수록 크게 부풀려진다 — 분모 350 이면 53.8% 가 85.3% 로 보인다
★ 같은 값을 쓰려면 score_total / total_points 다.  둘은 같다
for g, cut in grade_cuts:              # 0.90 · 0.80 · 0.70 · 0.60
    if ratio >= cut: return g
```

```
금지   total_points × 비율로 절대컷을 만들어 비교하는 것
      score_total >= 500  ✗
근거   분모가 매물마다 다르다.  절대컷은 축이 빠질수록 불리해진다
```

**실사고 — 절대컷을 쓰면 왜 깨지나**

```
★ 절대컷은 분모가 줄면 뜻을 잃는다 — 비율로 잰다
  ★ 분모가 만점보다 작아지면 ★ 같은 절대점수가 다른 비율이 된다
  축 하나가 빠지면 S 가 구조적으로 막힌다
  「모르면 분모에서 뺀다」의 취지와 정반대다
실측   203건 중 S 0 · A 0.  최고가 B 였다
검산   758.9/910 = 83.4% → A.  절대컷으로는 B 였다
```

| 등급 코드 | 비율 | 화면 표기 |
|:---:|:---:|---|
| `S` | 75% | S |
| `A` | 65% | A |
| `B` | 57% | B |
| `C` | 50% | C |
| `D` | 40% | D |
| `E` | 절대조건 | E |
| **`NOT_RATED`** | — | **평가 불가** |

```
★ 컷은 ★ 비율이다.  ★ 절대점수 열을 두지 않는다 —
  ★ 총점이 바뀌면 그 열이 낡는다 (개정 510)
★ 컷 값은 ★ f-table 5장-2a 가 정본이다
함수   grade_cut_points(policy)   ← display_points 가 아니다
      report/views.display_points 는 축 점수 표시(「—/20」)로 이미 쓰인다
      이름이 같으면 다른 것이 import 된다
검증   V4-21  같은 이름의 함수가 두 모듈에 없는가   code · warn
```

**`NOT_RATED` 는 등급이 아니라 「등급을 매길 수 없음」이다.**

```
발생   분모가 최소 기준(총점의 60%) 미만 (STEP 83-F)
       전 축 수집 실패 (STEP 83-D)
       금지 근거만 존재 (STEP 83-E)
금지   D 나 E 로 대체하는 것.  낮은 등급이 아니다
스키마  result_score.grade CHECK (grade IN ('S','A','B','C','D','E','NOT_RATED'))
```

```
S 는 499.5 를 올림한 500.  나머지는 내림
```
