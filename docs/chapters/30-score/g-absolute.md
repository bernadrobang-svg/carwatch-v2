## STEP 82 [판정] — E등급 절대조건

```
목적    점수와 무관하게 후보에서 제외할 조건을 정한다
원천    점검부 attributes · record 전손·침수 · condition.seizing · SalesStatus
값규칙  근거 필드가 NULL 이면 그 조건은 판정하지 않는다.  E 로 만들지 않는다
근거    되돌리기 어려운 판정이라 「모른다」를 「위험하다」로 바꾸지 않는다
금지    부위명 문자열로 골격을 판정하는 것.  RANK_A/B/C 를 쓴다
검산    E 판정 10종 각각의 근거 필드가 실제로 채워져 있는가

**점수와 무관하게 후보에서 제외한다. 되돌리기 어려운 판정이므로 근거를 엄격히 한다.**

| # | 조건 | 근거 필드 |
|:--:|---|---|
| 1 | 골격 손상 | `attributes` 에 `RANK_A/B/C` |
| 2 | 침수 | `master.detail.waterlog` · `record floodTotalLossCnt` |
| 3 | 에어백 전개 | 목록 `airbag_deployed` |
| 4 | 전손 | `record totalLossCnt` |
| 5 | **리스 상품 매물** | `advertisementType` · `advertisement.leaseRentInfo` (아래 정의) |
| 6 | 수리비 비율 초과 | `myAccidentCost` ÷ `price_origin_won` · `config.scoring.axis_rules.absolute_fail.repair_cost_ratio` |
| 7 | 렌트 + 보험이력 0 | 렌트인데 이력이 없음 = 은폐 의심 |
| 8 | 압류 | `seizingCount > 0` |
| 9 | 저당 | `pledgeCount > 0` |
| 10 | 계약중 · 판매완료 | `SalesStatus` |

## STEP 82c [판정] — 딜러 신뢰도 · 산출

```
목적    행태 지표를 하나의 상대 순위로 묶는다
원천    core_dealer 의 행태 지표 6종 (STEP 82b)
입력    DealerProfile
출력    trust_score (0~100) · quadrant (Q1~Q4)
값규칙  sample_sufficient=0 → trust_score = NULL.  quadrant 도 NULL
       0 점이 아니다.  「모른다」다
근거    지표는 딜러 신고값이 아니라 우리 관측값이라 조작이 어렵다
금지    표본 부족 딜러의 점수를 확정처럼 표시 (V3-26)
검산    trust_score 분포가 한쪽으로 쏠리면 가중치를 재검토한다

### 지표 정의

| 지표 | 산출 | 나쁜 방향 |
|---|---|---|
| `relist_rate` | 같은 `vehicle_id` 를 내렸다 다시 올린 비율 | **높을수록 나쁨** — 미끼 재게시 |
| `price_up_rate` | 게시 후 가격을 올린 비율 | **높을수록 나쁨** — 낚시 가격 |
| `price_volatility` | 가격 변동 폭의 표준편차 | 높을수록 나쁨 |
| `drop_event_rate` | 가격 인하 빈도 | **양면** — 정상 협상일 수도, 미끼일 수도 |
| `median_dom_days` | 게시 기간 중앙값 | 지나치게 길면 매물 품질 의심 |
| `info_score` | 광고 정보 충실도 | 낮을수록 나쁨 |
| `career_years` · `total_sales` | 경력 | 낮다고 나쁜 것은 아니다 |

```
필수   각 지표의 「나쁜 방향」을 명시한다
      drop_event_rate 처럼 양면인 지표는 단독으로 쓰지 않는다
```

### 종합 점수

```
trust_score = Σ(지표 × 가중치)          가중치는 config/dealer_trust.json
표시        0~100.  절대 기준이 아니라 상대 순위로 읽는다
```

### ★ 표본 부족 딜러

```
sample_sufficient = False   →  trust_score = None
표시                        점수 대신 「표본 부족 (N건)」
금지                        적은 표본의 점수를 확정처럼 보여주는 것
```

**신규 딜러가 나쁜 딜러가 아니다. 모르는 것을 나쁘다고 하지 않는다.**

### 4분면

```
가로   물량 (listing_count)
세로   신뢰도 (trust_score)

Q1  물량 많음 · 신뢰 높음      안전

Q3  물량 적음 · 신뢰 낮음      주의
Q4  물량 많음 · 신뢰 낮음      ★ 가장 위험

| 금지 | 이유 |
|---|---|
| **신호를 이유로 매물을 목록에서 제외** | 기회를 놓친다. 미끼가 아닐 수도 있다 |
| **신호를 555점에 합산** | 차량 가치와 거래 위험은 다른 축이다 |
| **신호를 이유로 등급을 내림** | 등급은 차량 상태다 |
| **추천 순위를 자동으로 내림** | 판단을 시스템이 대신하는 것이다 |

```
등급 severity 는 「얼마나 눈에 띄게 표시할 것인가」다.  처리 강도가 아니다

block   목록·상세 양쪽에 붉은 배지.  놓칠 수 없게
warn    목록에 배지 · 상세에 상세 설명
info    상세 화면에만
```

### 마스터 확인 체크 — 신호를 껐다 켤 수 있다

```sql
CREATE TABLE listing_warning (
  listing_id       TEXT NOT NULL,
  warning_code     TEXT NOT NULL,
  severity         TEXT NOT NULL,     -- block · warn · info  (표시 강도)
  evidence         TEXT NOT NULL,     -- 무엇이 · 얼마나 · 무엇과 비교해서
  detected_at      TEXT NOT NULL,
  last_seen_at     TEXT NOT NULL,
  resolved_at      TEXT,              -- 신호가 사라진 시각
  acknowledged     INTEGER NOT NULL DEFAULT 0,
  acknowledged_at  TEXT,
  ack_note         TEXT,              -- 「직접 확인함. 딜러 통화 완료」
  PRIMARY KEY (listing_id, warning_code),
  CHECK (severity IN ('block','warn','info'))
);
```

```
감지    실행마다 다시 감지한다.  기존 행이 있으면 last_seen_at 갱신
소멸    이번 실행에서 감지되지 않으면 resolved_at 을 채운다.  삭제하지 않는다
확인    acknowledged=1 → 목록에서 흐리게 · 알림 없음.  경고 자체는 남는다
재발    resolved 된 신호가 다시 감지되면 acknowledged 를 0 으로 되돌린다
```

**지우지 않는 이유** — 나중에 「왜 이걸 샀지」가 안 남는다.
`watch_candidate.score_snapshot` 과 같은 이유다.

```
동작   신호 옆에 「확인함」 체크박스
      체크하면 그 매물의 그 신호는 이후 배지를 흐리게 표시한다
      삭제하지 않는다.  기록은 남는다
용도   같은 신호를 매번 다시 판단하지 않게 한다
필수   ack 여부와 무관하게 신호 자체는 계속 감지·기록한다
금지   ack 를 이유로 감지를 멈추는 것.  상황이 바뀌면 다시 떠야 한다
```

**신호가 사라지면(예: 가격이 정상 범위로 회복) `ack` 도 만료시킨다.**

```
필수   신호마다 evidence 를 남긴다 — 무엇을 보고 판단했는가
      「의심스럽다」만 표시하면 마스터가 판단할 수 없다
      「기대가 3,900만 대비 −18%. 같은 조건 매물 중 최저 5%」처럼 낸다
```

### `price_too_low` — 가장 중요하고 가장 위험한 신호

```
논리   시세보다 지나치게 싸면 미끼일 수 있다
문제   그런데 「싸다」는 것이 이 시스템이 찾는 것이다
```

```
필수   가격 축은 그대로 만점을 준다.  점수를 깎지 않는다
      매물을 목록에서 빼지 않는다.  등급도 내리지 않는다
표시   「기대가 대비 −N%. 같은 조건 매물 중 하위 M%. 확인하십시오」
근거   판단은 마스터가 한다.  시스템은 사실과 통계적 위치만 낸다
임계   config.warnings.price_anomaly_sigma.  분포 기반이지 고정 금액이 아니다
```

**「미끼인가 기회인가」는 시스템이 답할 수 없다. 그래서 답하지 않는다.**

```

## STEP 83 [판정] — 채점 · 분모

```
목적    축 점수를 합쳐 총점을 낸다.  수집 실패가 점수로 둔갑하지 않게 한다
원천    result_axis 의 value · excluded · max_points
값규칙  분모 = 555 − Σ(excluded 축 배점).  NULL 이 아니라 excluded 가 결정한다
근거    분모의 절반이 빠진 매물과 전부 있는 매물을 같은 등급표로 비교할 수 없다
금지    보증 잔여 가치를 실구매가에서 차감하는 것 (가격 · 보증 이중 계산)
검산    분모 시험 6종 (A~F) 전건 통과 (V5-03)
```

### 산식

```
축 점수 합계 = Σ(축별 획득)
적용 가능 총점 = 555 − Σ(excluded=True 인 축의 배점)
최종 점수 = 축 점수 합계 ÷ 적용 가능 총점 × 555
```

### ★ `NULL` 이 분모 규칙을 결정하지 않는다 — `excluded` 가 결정한다

```
금지   if value is None: denominator -= weight     모든 NULL 이 자동 제외된다
금지   if value is None: score = 0                 모든 NULL 이 0점이 된다
필수   축마다 (value, excluded) 를 명시적으로 정한다.  AxisResult 에 함께 저장
```

| 상황 | value | excluded | 결과 |
|---|:---:|:---:|---|
| 장착 · 해당 | 1 | False | 만점 |
| 미장착 · 미해당 | 0 | False | 0점 |
| **실제로 만료·부재** | 0 또는 음수 | **False** | **감점 대상** |
| 구조적 부재 (차종 미제공) | −1 | **True** | 분모 축소 |
| 수집 실패 | NULL | **True** | 분모 축소 |
| 언급 없음 (틴팅) | NULL | **True** | 분모 축소 |
| 원본이 비어 있음 (`'[]'`) | 0 | False | 0점 |

**「없다」와 「모른다」를 같은 처리로 만들면 수집 실패가 점수로 둔갑한다.**

### 분모 시험 6종 — 필수 (0장 STEP 7.1)

```
A 전 축 정상            정상 점수
B 한 축 수집 실패        분모 제외 · 산출
C 한 축 구조적 부재      분모 제외 · 산출
D 전 축 수집 실패        점수 생성 금지
E 금지 근거만 존재       점수 생성 금지
F 분모 최소 기준 미만    등급 생성 금지 · '평가 불가'
```

```
최소 분모   총점의 60% 이상 권고.  config 에 둔다
근거       분모의 절반이 빠진 매물과 전부 있는 매물을 같은 등급표로 비교할 수 없다
표시       분모 미달은 '평가 불가'.  낮은 등급이 아니다
```

**「모든 축이 빠졌는데 평균 점수가 높게 나오는 것」을 반드시 차단한다.**

### 실구매가 · 총소유비용 — 점수와 분리 ★

**점수는 「이 차가 좋은가」다. 비용은 「얼마가 드는가」다. 섞지 않는다.**

```
표시가      current_price                          광고가
실구매가    표시가 + 취득 부대비용                    총 지출액
초기 현금    선납금 (부대비용 포함).  고정                   지금 나가는 돈
총소유비용   실구매가 + 보유 기간 × 월 유지비          보유 기간 전체
```

### 취득 부대비용 — 실구매가에 더한다

| 항목 | 산출 | config 키 |
|---|---|---|
| 취득세 | 취득가 × 세율 | `tax_acquisition_rate` |
| 공채 | 배기량·지역별 | `bond_table` |
| 인지·증지 | 고정 | `fee_stamp` |
| 이전 대행 | 딜러·법무 | `fee_transfer` |
| **탁송** | 거리 기반. 직접 인수면 0 | `fee_delivery` |
| 틴팅 등 인수 후 시공 | 미시공 시 예상 | `fee_tinting` |

```
전기차   취득세 감면 · 공채 면제가 있다.  차종별 적용 여부를 config 에 둔다
필수     각 항목을 「확정」과 「추정」으로 구분해 표시한다
        취득세는 확정.  탁송·틴팅은 추정
```

### 월 유지비 — 총소유비용에만 쓴다

```
자동차세 · 보험료 · 연료비 · 정비 예상
```

```
필수   전부 「추정」으로 표시한다.  실비가 아니다
필수   보유 기간을 마스터가 정한다.  기본값은 config
근거   연료비는 연료 종류로 크게 갈린다.  전기차와 가솔린을 같은 식으로 계산하지 않는다
금지   유지비를 점수 축에 넣는 것
```

### 금지

```
금지   보증 잔여 가치를 실구매가에서 빼는 것
      → 가격 200점과 보증 100점이 이중 계산된다 (v1 오류)
금지   총소유비용을 점수로 환산해 등급에 반영하는 것
      → 보유 기간 가정이 바뀌면 등급이 바뀐다.  등급은 차량 상태여야 한다
```

**비용은 같은 등급 안에서 고를 때 쓴다. 등급을 만드는 데 쓰지 않는다.**
