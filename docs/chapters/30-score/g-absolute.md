# ★★★ 원문이 없는데 「무사고」로 판정했다 — 08-17

**마스터 지적 — 「보험이력도 없어. 성능기록도 없어. 왜 이렇게 S 등급이냐」**

## 이것이 진짜 원인이다

```
화면    사고 무사고 · 골격 이상 없음 · 보험 수리비 0원 · 보증 1년 3개월
실제    그 원문을 못 받았을 수 있다
★ 원문이 없으면 「무사고」가 아니라 「확인 못 함」이다
  「수리비 0원」이 아니라 「모름」이다
```

```
★ v1 사고와 같은 유형이다
  v1   「[] 가 NULL 로 저장돼 분모에서 빠졌다」
  v2   「원문이 없는데 없음이 무사고로 저장됐다」
★ 개정 289 「못 본 축은 0점」이 안 지켜지고 있다
```

## 규격

```
필수   원문이 없으면 축은 「확인 못 함」이다.  값을 만들지 않는다
       ★ record 원문이 없으면 사고·보험은 ? 다
       ★ inspection 원문이 없으면 골격·틴팅은 ? 다
필수   「없음」과 「확인 못 함」을 파서 단계에서 가른다
       원문에 「사고 없음」이 적혀 있다      →  없음   O
       원문 자체가 없다                    →  모름   ?
       원문은 있는데 그 항목이 없다          →  모름   ?
       ★ 셋을 같은 값으로 저장하면 여기서 끝난다
필수   화면에 그대로 낸다
       「사고 — 보험이력을 받지 못했습니다」
필수   점수는 0 이다 (개정 289).  마이너스는 아니다
       ★ 우리가 못 받은 것으로 벌을 주지는 않는다
       ★ 다만 「확인 못 한 것 N점」이 커지므로 비율이 낮아진다
금지   원문 없이 기본값을 넣는 것
검산   V3-62  원문이 없는 축이 「없음」으로 저장되지 않았는가
       V3-63  화면의 「무사고」가 실제 원문 근거를 갖는가
```

```
★ 이 검사가 가장 급하다
  지금 등급이 「받지도 않은 것을 좋다고 판정한」 결과일 수 있다
필수   전 3,470건에서 세어라
```

# ★★★ 등급 경계는 절대 기준이다 — 08-17

**마스터 지적 — 「468점이 S 등급인 이유가 뭐냐」**

## 실측

```
468 / 605 = 77.4%   →  S
0점인 축이 110점 (18%)
  우수등급 0/30 · 옵션 0/30 · 용도 0/25 · HUD 0/15 · 선루프 0/10
★ 이것은 08-17 당시의 실측이다.  그때 분모는 605 · ⑤ 보증 30 이었다
  지금은 ★ 분모가 총점 하나다 (개정 365·392·454 · 5장-2a)
  ★ 기록이라 숫자를 고치지 않는다.  근거로 삼지 않는다 (개정 404)
```

## 왜 이렇게 됐나

```
등급 경계를 백분위로 잡았다 — S = 상위 1% · A = 상위 5%
★ 그것은 상대 기준이다
  전체가 나쁘면 나쁜 차가 S 가 된다
  「우리가 가진 것 중 제일 나은 것」이지 「좋은 차」가 아니다
```

## 규격

```
필수   등급 경계는 절대 기준이다.  백분위로 잡지 않는다
       S   90% 이상   거의 흠이 없다
       A   80~90      좋다
       B   70~80      쓸 만하다
       C   60~70      보통
       D   50~60      아쉽다
       E   50 미만 또는 절대 배제
필수   그 등급이 한 건도 없어도 그대로 둔다
       ★ 「S 가 0건」이 사실이면 그것이 정보다
       ★ 억지로 채우려고 경계를 내리지 않는다
필수   분포를 화면에 낸다 — 「이 조건에 S 0건 · A 12건 · B 340건」
필수   경계는 config — scoring.grade_thresholds
금지   백분위로 경계를 정하는 것
       ★ 표본이 바뀔 때마다 등급의 뜻이 바뀐다
       ★ 어제 A 였던 차가 오늘 B 가 된다
검산   V3-64  등급 경계가 config 의 절대값과 같은가
```

```
★ 왜 절대 기준인가
  사람이 「S 등급」을 보고 기대하는 것은 「거의 흠이 없다」이다
  「우리 표본 중 상위 1%」가 아니다
★ 그리고 사이트를 늘리면 표본이 바뀐다
  K카를 넣었더니 어제 S 가 오늘 A 가 되면 못 믿는다
```

# ★★★ 「확인율 100%」가 거짓이었다 — 08-17

```
화면   「카탈로그 미조회 → 사양 축 판정 불가」
      「엔카 자체진단 미조회 → 이 매물은 미진단」
      그 아래
      「확인 못 한 것 — 없습니다.  17 Component 전부 판정됐습니다 — 확인율 100%」
```

```
★ 안 부른 것이 둘인데 확인율 100% 다
★ 「축이 전부 계산됐다」와 「전부 확인됐다」를 같은 말로 쓰고 있다
  0점도 「판정됐다」로 세고 있다
```

```
필수   확인율은 「근거가 있는 축의 배점 합」 ÷ 만점 이다
       ★ 0점이어도 근거가 있으면 확인된 것이다
         「HUD 없음 — 옵션 코드에 없다」  →  확인됨 · 0점
       ★ 근거가 없으면 확인 안 된 것이다
         「사양 축 — 카탈로그를 안 받았다」  →  확인 안 됨 · 0점
필수   둘을 화면에서 가른다
       「확인 100% 중 0점 110점」  ≠  「확인 82% · 미확인 110점」
필수   「미조회」와 「조회했으나 없음」을 가른다
       ★ 화면 위쪽 표에는 이미 있다.  아래 문장이 그것을 무시한다
금지   0점을 「판정됐다」로 세는 것
검산   V3-65  확인율이 근거 있는 축만 세는가
       V11-105  화면 위아래가 서로 어긋나지 않는가
```
