# 2. 설계도 — ★ 네 걸음

```
 ┌── 1걸음 · 받기 ────────────────────────────────────────┐
 │  사이트 → 파일.  ★ DB 를 안 연다                        │

 └────────────────────────────────────────────────────────┘

 │  파일 → ★ 임시표 `stage_listing`                        │

 └────────────────────────────────────────────────────────┘
                        ↓
 ┌── 3걸음 · 맞대기 ──────────────────────────────────────┐
 │  임시표 ↔ core_listing 을 ★ source_id 로 대본다          │
```

## ★ 임시표 `stage_listing` — 왜 필요한가

```
★ 마스터 — 「★ 파서가 데이터에서 갖다 불러와서 데이터에 집어넣기 위해서는
   ★ **임시 테이블도 필요하면 임시 테이블도 필요할 거야** …
   ★ 파일 중에서 모든 데이터를 뽑아서 ★ 그 필드 데이터를 뽑아서 …
   ★ **신규일 땐 다 그렇게 해야** 되는 거고」

까닭 셋
  ① ★ 맞대기를 하려면 ★ 「이번에 받은 것」이 ★ 한 자리에 있어야 한다
  ② ★ 파싱이 틀려도 ★ core_listing 이 안 더러워진다 — ★ 임시표만 버린다
  ③ ★ ★ **가이드가 여기서 검증한다** — ★ 「값이 제대로 뽑혔나」를 임시표로 본다

꼴   core_listing 과 ★ 같은 칸 ＋ `run_id` · `file_path`
     ★ 한 회차가 끝나면 ★ 비운다.  ★ 원문은 파일에 남는다
```

# 6. 차례 — ★ 이대로 가도 되는지 여쭙는다

```
① 파일 받기 (엔카 뺀 아홉)          ← 개발측
② 임시표 `stage_listing` 신설       ← 개발측
③ 파서가 파일 → 임시표              ← 개발측 (파서 결함 여섯을 여기서 함께 고친다)
④ ★ 가이드가 임시표로 검증          ← 가이드
⑤ 맞대기(신규·변경·상태)            ← 개발측
⑥ 원문 옮기고 대조 → `raw_response` 지우기  ← 개발측
⑦ 팔린 차 화면 · 가격 통계          ← 개발측
```

★ **마스터께 여쭙는다 — ★ 이 설계도가 맞습니까**
   ★ A ★ 이대로 간다
   ★ B ★ 임시표를 안 만들고 ★ 파일에서 바로 맞댄다 (★ 더 단순하나 ★ 검증 자리가 없다)
   ★ C ★ 고칠 데가 있다 — ★ 말씀해 주시면 고쳐서 다시 올린다
★ ★ 가이드 안은 ★ **A** 다.  ★ 까닭 — ★ ④ 검증 자리가 ★ 오늘까지 없어서 ★ 오판 188~193 이 났다
