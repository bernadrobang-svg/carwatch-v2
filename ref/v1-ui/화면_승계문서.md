## 2. 왜 이렇게 만들었나

### 2.1 판정 근거 화면(`/why`)이 핵심입니다

```
등급만 보면 왜 그런지 알 수 없다.
'B등급 422점' 만으로는 살지 말지 정할 수 없다.

  가격  100/200   기대가 3,913만 · 실매물 3,470만 (-444만)
  보증   88/100   일반 29개월 · 파워트레인 41개월
  이력   36/55    무사고 · 보험 내차피해 0원
  사양   58/90    HUD O · 선루프 X · HDA 1단계

축마다 '무엇을 근거로' 를 함께 낸다.
```

**v2 는 `result_axis` 에 `source`·`prio` 가 있으므로 이 화면이 더 정확해집니다.**

### 2.2 색은 의미로만 씁니다

```
  --bg:#0e1013; --surface:#161a1e; --surface2:#1d2228;
  --line:#262c33; --line2:#333b44;
  --text:#e4e2df; --dim:#8b939c; --faint:#5a626b;
  --amber:#e8a13a;          /* 계기판 조명 — 강조는 여기만 */
  --down:#4fc3a1;           /* 인하 = 좋음 */
  --up:#e0655f;             /* 인상 = 나쁨 */
  --gone:#7d8590;
  --mono:ui-monospace,'JetBrains Mono','Cascadia Mono','D2Coding',
  --sans:-apple-system,BlinkMacSystemFont,'Pretendard','Segoe UI',
```

```
amber   계기판 조명.  강조는 여기 하나뿐이다
down    가격 인하 = 좋음  (초록)
up      가격 인상 = 나쁨  (빨강)
gone    소진된 매물     (회색)

★ 등급(S/A/B/C/D/E)에 색을 쓰지 않는다.
  색이 6개면 아무것도 강조되지 않는다.
```

### 2.3 숫자는 고정폭, 글자는 가변폭

```
--mono  가격 · 주행 · 점수     자릿수가 세로로 맞아야 비교된다
--sans  트림 · 딜러명 · 사유
```

### 2.4 어두운 배경

```
밤에 오래 본다.  차 고르는 일은 퇴근 후에 한다.
흰 배경이면 눈이 아프다.
```

## 3. 기술 스택

```
서버    Flask  (web/app.py 단일 파일)
템플릿   Jinja2
CSS     base.html 안에 인라인.  빌드 도구 없음
JS      바닐라.  프레임워크 없음
폴링    /api/run/status 를 2초마다
```

**의도적으로 빌드 단계를 두지 않았습니다.**

```
이유   1인 도구다.  npm install 이 필요하면 6개월 뒤에 안 돈다.
     브라우저에서 F5 만 누르면 반영되는 게 낫다.
```

## 4. v2 로 옮길 때 지킬 것

### 4.1 반드시 유지

| 항목 | 이유 |
|---|---|
| `/why` 판정 근거 화면 | 이 도구의 존재 이유 |
| 색 4종 제한 | 늘리면 강조가 사라진다 |
| 숫자 고정폭 | 자릿수 비교가 안 되면 표가 무의미 |
| 빌드 도구 없음 | 유지보수 비용 |
| 폴링 방식 진행률 | WebSocket 은 과잉 |

### 4.2 반드시 고칠 것

| 항목 | 현재 | v2 |
|---|---|---|
| 권한 | 없음. 누구나 수집 실행 | STEP 126 권한 3단 |
| `/run` 노출 | 비로그인도 수집 시작 가능 | admin 전용 |
| DB 직접 조회 | 화면이 SQL 을 짠다 | STEP 1 — DTO 경유 |
| 컬럼명 | `insp_*` · `encar_*` 사이트 고유명 | `core_*` 뷰 |
| 관리자 화면 | 없음 | STEP 138 |

**`/run` 이 권한 없이 열려 있는 것이 가장 큰 문제입니다.**

```
지금   브라우저로 접근하면 누구나 수집을 돌릴 수 있다
v2    require_role(acc, 'admin') 를 라우트 진입점마다
```

### 4.3 옮기지 말 것

```
web/app.py 의 SQL 직접 조회
  화면이 352컬럼 Row 를 그대로 읽는다.
  v2 는 core_listing 뷰 또는 DTO 를 거친다.

템플릿 안의 계산
  {{ (it.current_price - it.warranty_value)|manwon }} 같은 것.
  이미 제거했으나 남은 게 있을 수 있다.
  화면은 표시만 한다.
```

## 5. 화면별 인수인계

### `/`

- 차종별 카드 · 등급 분포 막대 · 오늘 변동
- 새로고침 없이 /api/summary 로 갱신

### `/recommend`

- 1~3순위. 점수순이 아니라 recommend_rank 순
- 미확인 손실(unknown_loss)을 함께 낸다
- ★ '확인만 되면 B 이상' 표시가 중요하다

### `/listings`

- 축·값으로 거르는 링크가 태그마다 붙는다
- 예: HUD 있음 → ?axis=hud&bucket=1

### `/why/<id>`

- ★ 축별 점수 + 근거 + 계산 과정
- v2 result_axis 로 바꾸면 source·prio 도 낼 수 있다

### `/compare`

- 최대 3대. 최종 후보 지정
- v2 watch_candidate 테이블로 이관

### `/run`

- ★ 권한 없음. v2 에서 admin 전용으로
- SSE 아니고 2초 폴링. 단순해서 안 깨진다
