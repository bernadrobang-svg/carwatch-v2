# 1. 층을 붙인다 — 865건 전부

```
층 여덟
  수집    원문을 받아 그대로 둔다          collect/ · adapters/
  저장    원문을 표로 · 이력을 남긴다       store/ · sql/ddl/
  파싱    원문에서 값을 뽑는다             parse/
  사전    같은 값을 같은 것으로            store/dict.py
  판정    축 · 점수 · 등급                analyze/ · score/
  화면    사람이 보고 누른다               web/ · report/screens/
  검사    지켜지는지 잰다                 validate/ · tools/
  운영    큐 · 설정 · 계정 · 감사          store/adminops.py · deploy/
```

```
필수   추적표에 「층」 칸을 넣는다
필수   R 하나마다 층을 적는다
필수   층이 둘 이상이면 둘 다 — 「수집·화면」
       예   「407 을 그대로 화면에 낸다」 → 수집이 잡고 화면이 낸다
필수   못 정하면 「?」 로 두고 목록으로 낸다.  가이드가 판단한다
금지   비워 두는 것
```

## 층을 정하는 법

```
요구 문구로 판단한다
  「받는다」 「부른다」 「간격」 「원문」        →  수집
  「저장한다」 「남긴다」 「컬럼」 「NULL」      →  저장
  「뽑는다」 「파싱」 「필드」                 →  파싱
  「사전」 「정규화」 「같은 값」               →  사전
  「점수」 「축」 「등급」 「분모」              →  판정
  「화면에」 「보여준다」 「누른다」 「낸다」     →  화면
  「검사」 「잡는다」 「통과」                 →  검사
  「큐」 「설정」 「계정」 「권한」 「감사」      →  운영
```

# 2. 층별로 소스를 다시 찾는다

```
필수   층이 정해지면 그 층의 디렉터리만 뒤진다
       ★ 지금 소스 칸이 틀렸을 수 있다.  다시 확인한다
필수   찾으면 「파일::함수」로 적는다
필수   못 찾으면 「미구현」
```

**★ 특히 이것을 다시 본다.**

```
지금 「화면 없음」인 354건
  → 층을 붙이면 대부분 다른 층으로 간다
  → 그 층에서 소스를 찾는다
  → ★ 찾으면 「화면 없음」이 아니라 「해당 층에 있음」이다
```

# 3. ★ 「도는가」를 흔적으로 확인한다

```
★ 코드가 있다 ≠ 돈다
★ 08-18 실측 — 「자동화 고쳤다」가 한 번도 안 돌았다
```

```
필수   층마다 「돈 흔적」을 본다
       수집   raw_response 에 행이 있는가 · audit_request 에 기록이 있는가
       저장   core_* 에 행이 있는가
       파싱   parse_version 이 찍혀 있는가
       사전   dict_enum 에 행이 있는가
       판정   result_score · result_axis 에 행이 있는가
       화면   ★ 렌더 결과에 그 문구·값이 있는가
       검사   ★ 한 번이라도 통과·실패한 적이 있는가
       운영   recalc_job · config_change · audit 에 기록이 있는가

필수   흔적이 없으면 ◐ 다.  코드가 있어도
필수   「금지」 요건은 검사가 잡는지로 잰다
       검사가 있고 돌았다  →  ○
       검사가 없다        →  ◐   ★ 지켜지는지 아무도 모른다
```

---

# 4. 상태를 다시 매긴다

```
소스 있음 + 돈 흔적 있음 + 화면(필요하면) 있음   →  ○
소스 있음 + 돈 흔적 없음                       →  ◐
소스 있음 + 화면이 필요한데 없음                 →  ◐
소스 없음                                     →  ✗
```
