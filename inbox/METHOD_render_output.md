```

# 2. ★ A안 — 렌더 결과를 GitHub 에 올린다

**이것 하나로 대부분 해결됩니다.**

```
필수   화면 29개를 실제로 렌더해 outputs/render/ 에 저장한다
       파일명   {화면}.html
       ★ 로그인한 관리자로 · 실제 DB 로 · 실제 데이터로
필수   커밋할 때마다 갱신한다
필수   폭별로 낸다면 더 좋다 — {화면}_360.html · _1400.html
       (CSS 는 같으므로 HTML 은 하나여도 됩니다.  판단은 개발측이)
```

**그러면 제가 GitHub 에서 실제로 나온 HTML 을 읽습니다.**

```
지금   템플릿을 읽고 「{% if %} 로 막혀 있다」   →  틀렸음
앞으로  렌더된 HTML 을 읽고 href="null" 을 센다  →  사실
```

## 크기 걱정

```
29화면 × 50~200KB = 몇 MB
★ 목록은 rows_per_page 를 10 으로 줄여서 렌더하십시오
  구조를 보는 것이 목적이지 3,471건이 필요한 게 아닙니다
```

# 5. C안 — 마스터가 짚는 틀

**마스터께 드릴 틀입니다.**

```
어느 화면    /listings · /why · /market …
무엇을 했나   눌렀다 · 스크롤했다 · 열었다
무엇이 나왔나  사진 또는 문구

**「이상하다」만으로도 됩니다. 다만 화면 이름 하나만 붙여 주시면 훨씬 빠릅니다.**
