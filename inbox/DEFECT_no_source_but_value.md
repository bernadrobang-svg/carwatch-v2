# 1. 개정 322 — 상한 폐기. 마이너스 점수로

```
마스터   「이런 것 필요없어.  이것은 모두 마이너스 점수 주면 돼」
```

**맞습니다. 상한은 점수제 밖의 규칙이라 뜻이 흐려집니다.**

```
렌트·영업용 이력        −50
사이트 우수등급 없음     −30
자차 미가입 30% 이상    −40
점검을 판매자가 등록     −20
사고 1회당             −25  (누적)
골격 판금              −40
골격 용접·교환          −80
```

```
필수   마이너스는 총점에서 뺀다.  0 아래로도 내려간다
       ★ 「0점이 바닥」이 아닙니다.  흠이 겹치면 음수입니다
필수   화면에 뺀 것을 낸다 — 「렌트 이력 −50 · 우수등급 없음 −30」
필수   config — scoring.penalties
금지   상한 같은 별도 장치를 늘리는 것
       ★ E 등급 절대 배제만 남깁니다 — 그건 「살 수 없는 것」입니다
```

**★ 이 매물은 렌트(−50) + 우수등급 없음(−30) = −80 입니다.**
**433 → 353 · 63.6% → C 로 내려갑니다.**

# 2. ★★★ 개정 323 — 진짜 원인은 이것입니다

```
화면   사고 무사고 · 골격 이상 없음 · 보험 수리비 0원 · 보증 1년 3개월
```

**마스터 말씀은 「그 원문을 받지도 않았는데 왜 값이 있냐」입니다.**

```
★ 원문이 없으면 「무사고」가 아니라 「확인 못 함」입니다
  「수리비 0원」이 아니라 「모름」입니다
★ v1 사고와 같은 유형입니다
  v1   「[] 가 NULL 로 저장돼 분모에서 빠졌다」
  v2   「원문이 없는데 없음이 무사고로 저장됐다」
```

## 규격

```
필수   원문이 없으면 축은 「확인 못 함」이다.  값을 만들지 않는다
필수   셋을 파서 단계에서 가른다
       원문에 「사고 없음」이 적혀 있다   →  없음   O
       원문 자체가 없다                 →  모름   ?
       원문은 있는데 그 항목이 없다       →  모름   ?
       ★ 셋을 같은 값으로 저장하면 여기서 끝납니다
필수   화면에 — 「사고 — 보험이력을 받지 못했습니다」
필수   점수는 0.  마이너스는 아니다
       ★ 우리가 못 받은 것으로 벌을 주지는 않습니다
       ★ 다만 「확인 못 한 것」이 커져 비율이 낮아집니다
금지   원문 없이 기본값을 넣는 것
검산   V3-62 · V3-63
```
