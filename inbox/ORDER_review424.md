## 왜 이렇게 잡았나 — 마스터 요구 다섯

```
① 보증이 없어도 값·옵션·색이 다 좋으면 A 에 닿는다
② 보증이 있고 값도 좋으면 S 에 닿는다
③ 값이 안 맞으면 아무리 성해도 A 가 안 된다
④ 제조사 보증이 사이트 검증보다 크다  (1.5:1)
⑤ 사이트 검증도 혼자서 순위를 가를 만큼은 된다
```

# 2. ★ 개발측에 묻는 것 — 재계산

## 2-1. 갈래 배점만 바꾸면 recalc 를 돌려야 하나

```
result_axis 에 축별 점수가 이미 앉아 있다
★ 갈래 배점이 바뀌면 축 배점도 바뀌므로 축 점수 자체가 바뀐다 — 맞나
★ 아니면 축 점수는 「몇 %를 채웠나」로 저장돼 있어 배점만 곱하면 되나
필수   실제 스키마를 열어 답한다.  ★ 짐작으로 답하지 않는다
```

## 2-2. 축 온·오프는 recalc 없이 되나

```
마스터가 「선루프는 안 본다」 하면 그 축을 끄고 ★ 분모에서 뺀다 (675 → 665)
가이드 판단   result_axis 에서 그 행을 빼고 다시 더하면 화면에서 즉시 된다
★ 맞나.  200건 × 24축을 화면에서 더하는 것이 무겁지 않나
★ 무거우면 어디에 두는 것이 낫나
```

## 2-3. 점수 필터를 SQL 로 걸 수 있나

```
「값 점수 220 이상」 「취향 60 이상」을 필터로 건다
★ result_score 에 갈래별 합이 있나, 아니면 매번 result_axis 를 더해야 하나
★ 후자면 건수·쪽 계산이 어긋난다 (V11-55).  어떻게 푸는 것이 좋나
```

## 2-4. 얼마나 걸리나

```
필수   전건 recalc 에 걸리는 시간을 실측으로 답한다
필수   ★ 마스터가 취향을 바꾸실 때마다 돌려야 하는지, 아닌지를 갈라 답한다
```
