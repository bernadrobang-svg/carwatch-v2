# 1. 개정 419 — 값 축을 비례식으로

**정본은 `docs/chapters/30-score/f-table.md` ①-1 · ①-2 다.**

```
1-1 시세 대비 100    점수 = round(r% × 5)    범위 −100 ~ +100
1-2 신차가 대비 80   점수 = round(d% × 1)    범위 −20 ~ +80
★ 계단표를 없앤다 — market_curve · depreciation_curve · residual_by_year 폐기
```

## 왜 바꾸나 — 실측

```
전   market_curve 는 시세와 같을 때 50/100 을 준다
     ★ 비싼 매물이 그 50점을 그냥 받았다
     −20% 에서 바닥.  35% 비싸도 0점으로 같았다
     ★ 무사고면 ②150 + ③80 + ⑤⑦100 = 330/625 가 값을 안 보고 깔린다
     그래서 「사고 없다고 A 인데 값은 비싸다」가 나온다
후   시세와 같으면 0점.  비쌀수록 계속 깎여 다른 축이 번 점수를 실제로 깎는다
```

## 마스터 검산

```
신차 30% 싸다 + 시세 5% 싸다   →  30×1 + 5×5 = 55      ★ 마스터 「55점」
신차 10% 싸다 + 시세 3% 비싸다  →  10×1 − 3×5 = −5      ★ 마스터 「−5점」
```

```
필수   config/scoring.json axis_rules.value 를 바꾼다
       market_per_percent 5 · market_min −100 · market_max 100
       origin_per_percent 1 · origin_min −20 · origin_max 80
       ★ 계수를 코드에 박지 않는다 (S14 · V4-13)
필수   폐기 키를 지운다 — market_curve · depreciation_curve
       residual_by_year · residual_step · residual_floor
필수   ★ 총점 675 는 그대로다.  ① 값 갈래 표기 250 도 그대로 — V3-77 이 문다
필수   화면에 부호를 그대로 낸다 — 「3.0% 비쌉니다 → −15점」
금지   0 에서 멈추는 바닥
금지   residual_by_year 로 되돌리는 것
검산   V3-82  시세 점수가 계단값만 나오는가 (나오면 실패)
       V3-83  시세보다 비싼 매물에 음수 점수가 붙는가
       V3-84  신차가 점수가 d% 와 1:1 인가
```

## ★ 돌린 뒤 반드시 낼 것

```
필수   등급 분포 전후 표 — S · A · B · C · D · E · NOT_RATED
필수   ★ 값 점수가 음수인 매물 수와 그 등급 분포
필수   ★ 「무사고인데 시세보다 비싼」 매물의 등급이 실제로 내려갔는지 표본 5건
필수   ★ 「B 등급인데 값이 싸고 무사고·저주행」인 매물이 올라갔는지 표본 5건
       근거 — 마스터 「B 등급인데 가격이 매력적이고 무사고에 킬로가 적은 것도 있고」
```

# 2. 개정 420 — 리스·렌트를 목록에서 뺀다

**마스터 확정 — 「리스는 목록에서 아예 뺀다」**

```
입력   advertisementType == "OPERATING_LEASE"   ★ 정규식 없이 갈린다
      LeaseType 4값 — 렌트승계 · 운용리스 · 장기렌트 · 금융리스
      SellType — 일반 · 렌트 · 리스
```

```
필수 [마스터]  리스·렌트는 /listings · /recommend 에 나오지 않는다
필수         ★ 지우지 않는다.  저장은 그대로 하고 화면에서만 뺀다 (P3)
필수         건수는 낸다 — 「리스·렌트 N건은 뺐습니다」
필수         ?lease=1 로 볼 수 있게 한다.  ★ 기본은 숨김
금지         수집 단계에서 안 받는 것.  ★ 기준이 바뀌면 다시 못 받는다
금지         조용히 빼는 것.  건수를 안 내면 매물이 사라진 것으로 보인다
검산   V11-153  기본 목록에 리스·렌트가 섞여 있는가
       V11-154  뺀 건수가 화면에 있는가
```

# 3. 개정 420 — 목록 필터에 차종·가격대

```
★ STEP 149d 는 축·값 필터(?axis=hud&bucket=1)만 정했다
★ 차를 사는 사람이 제일 먼저 쓰는 조건이 빠져 있었다
```

| 필터 | 파라미터 | 모양 |
|---|---|---|
| 차종 | `?model=G80` | 드롭다운 — 등록부에 있는 차종만 |
| 가격대 | `?price_min=2000&price_max=3500` | 만원 단위 |
| 리스 | `?lease=1` | 체크 · 기본 꺼짐 |
| 등급 | `?grade=A,B` | 있으면 그대로 |

```
필수   필터를 목록 위에 둔다 (V11-66)
필수   ★ 필터가 그대로 요청 파라미터가 된다 (STEP 149g)
       관심 등록 · 비교 · 알림이 그 조건을 그대로 쓴다
필수   고른 조건을 문장으로 — 「G80 · 2,000~3,500만 · 리스 제외 — 34건」
필수   ★ 값이 없는 조건은 URL 에 안 넣는다
금지   필터를 걸면 정렬이 풀리는 것
검산   V11-155  차종·가격대 필터가 있는가
       V11-156  필터 조건이 관심·비교·알림에 그대로 넘어가는가
```
