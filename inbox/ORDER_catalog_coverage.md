# ★★★ 개정 327·328 — 카탈로그를 왜 안 받았나

**마스터 지적 — 「카탈로그가 왜 없어. 수집하다가 버린 거겠지. 가중치 미반영에」**

---

# 1. 지금 아는 것

```
카탈로그   08-16 21건 → 전 차종 수집 후 147건
매물      3,470건
```

```
★ 카탈로그는 「모델·연식·트림」 조합 단위입니다
★ 그 조합이 몇 개인지를 센 적이 없습니다
★ 그러니 147건이 많은지 적은지도 모릅니다
```

---

# 2. ★★★ 지금 당장 세십시오

```sql
-- 필요한 조합
SELECT COUNT(DISTINCT model_cd || '|' || form_year || '|' || trim_code)
FROM core_listing WHERE target_key IS NOT NULL;

-- 조합별 매물 수 (상위 30)
SELECT model_cd, form_year, trim_code, COUNT(*) n
FROM core_listing WHERE target_key IS NOT NULL
GROUP BY 1,2,3 ORDER BY n DESC LIMIT 30;

-- 받은 카탈로그가 매물과 이어지는가
-- 147건 중 매물에 매칭되는 것이 몇 건인가
```

```
필수   답할 것
  ① 필요한 조합 수
  ② 받은 조합 수 (147)
  ③ 비율
  ④ 못 받은 것의 사유별 건수
     not_called    ★ 안 불렀다 — 우리 잘못
     http_404      그 조합이 없다
     http_error    다른 오류
     parse_failed  받았는데 못 읽었다
  ⑤ 받은 147건 중 매물과 이어진 것 몇 건
     ★ 안 이어지면 받은 것이 아닙니다
  ⑥ 옵션가를 낼 수 있는 매물 몇 건 / 3,470
```

**★ ④ 에서 `not_called` 가 많으면 마스터 말씀이 맞습니다.**

# 3. 규격 — 개정 327

```
필수   필요한 조합을 먼저 센다.  매물에서 나온 것만 받지 않는다
필수   못 받은 조합을 사유와 함께 기록한다
필수   매칭 키를 검사한다
       ★ 받았는데 매물과 안 이어지면 받은 것이 아닙니다
필수   조합별 매물 수를 함께 낸다
       ★ 매물 300건이 걸린 조합과 1건짜리는 급한 정도가 다릅니다
금지   조합 수를 모르는 채로 「카탈로그 147건」이라고만 하는 것
검산   V1-23 · V1-24
```

# 4. ★ 개정 328 — 「가중치 미반영에」

**마스터 지적의 뒷부분입니다.**

```
카탈로그 없음  →  옵션 축 30점이 통째로 0
그런데 화면은  「확인율 100%」
★ 30점이 빠진 것이 화면에 안 나타납니다
```

```
필수   근거 없어 0점인 축의 배점을 「미확인 점수」로 합산한다
       「미확인 30점 — 카탈로그를 못 받았습니다」
필수   미확인 점수가 큰 순으로 관리 화면에
       「옵션 축 미확인 2,900건 · 87,000점」
       → 카탈로그를 받으면 그만큼이 살아납니다
필수   무엇을 받으면 무엇이 살아나는지 잇는다
       카탈로그 → 옵션 30 · 사양
       엔카진단 → 우수등급 30
       record  → 사고 70 · 보험 30 · 용도 25
       ★ 「무엇을 먼저 받아야 하나」가 이 표에서 나옵니다
검산   V3-67
```
