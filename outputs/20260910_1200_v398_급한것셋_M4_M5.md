## 2. ★ 급한 것 1 — 상세 62 → 5 는 **상태가 되돌아간 것이 아니다.  내가 자를 바꿨다**

## 3. ★ 급한 것 2 — `no such table: core_listing`

### 표 이름이 바뀐 것도 DB 가 갈린 것도 아니다. **자를 그 자리에서만 돌게 만들어 놨다**

v397 에서 「원문」을 `raw_response`(비우기로 정한 표) 대신 **파일**로 세게 고치며
`raw_file_counts()` 를 넣었다. 그것이 `carwatch.db` 를 연다.

**그런데 `carwatch.db` 와 `raw/` 는 git 에 안 올라간다** (`.gitignore:4`).
그리고 `sqlite3.connect` 는 **없는 파일을 조용히 만든다.**

```
가이드 장비   git pull → carwatch.db 가 없다
             sqlite3.connect("carwatch.db")  → 빈 파일이 생긴다
             SELECT ... FROM core_listing    → no such table: core_listing
```

재현해 확인했다. 서버에서는 그래서 멀쩡히 돌았고, 밖에서만 죽었다.

### 고쳤다

* `mode=ro` 로 연다 — **없으면 안 만들고 그냥 못 잰다**
* 못 재면 그 칸을 **안 낸다** — 0 으로 두면 거짓 「구멍」이 된다 (금지 12)
* 한 줄로 말한다: `원문 — 이 자리에서는 못 잰다 (carwatch.db · raw/ 는 서버에만 있다)`

### `/status` 404 는 정상이다

그런 길이 **없다**. 관리 화면은 `/admin/status` 다 (`web/routes.py:111`).
공개 상태 쪽이 필요하시면 만들겠습니다 — 지금은 없는 것이 맞습니다.
