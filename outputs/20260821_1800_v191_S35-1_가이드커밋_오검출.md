## 3. 원인 — 「누가 고쳤나」를 안 보고 있었다

`tools/check_src.py:1084`

```python
_rc2, _diff = _git("diff", "--stat", "HEAD~1", "--",
                   "docs/guide", "docs/chapters")
if not _rc2 and _diff.strip():
    _b351.append("개발측이 지시서를 고쳤다 — " + …)
```

`HEAD~1` 과의 차이만 본다. **그 차이를 누가 만들었는지는 안 본다.**

```
git reflog -8
  10cff0c HEAD@{0}: pull -q: Fast-forward      ★ 받아온 것이다
  d511306 HEAD@{1}: commit (amend): V3-86·V3-87 …

git log -3 --format='%h | ce=%ce'
  b69708f | ce=bernadrobang@users.noreply.github.com   ← 이 장비가 만든 것
  10cff0c | ce=bernadro.bang@gmail.com                 ← 가이드가 GitHub 에서
  d7380f8 | ce=bernadro.bang@gmail.com                 ← 가이드가 GitHub 에서
```

`10cff0c` 는 가이드가 개정 431 을 올린 커밋이다.
**규칙 9 (08-16 부터 가이드가 GitHub 에 직접 push 한다) 가 생긴 뒤로
「HEAD~1 과 다르면 개발측이 고친 것」이 성립하지 않는다.**
검사가 규칙 9 보다 먼저 쓰여 그대로 남아 있었다.

★ 이 오검출은 위험하다 — **규칙 2 위반 경보가 늘 켜져 있으면 진짜 위반을
아무도 못 본다.**

## 4. 무엇을 했나

`tools/check_src.py` S35-1 — 두 갈래로 나눠 본다.

```
① 아직 커밋 안 한 docs 수정        → 언제나 개발측의 것이다.  그대로 잡는다
   git diff --stat HEAD -- docs/guide docs/chapters
② 커밋된 docs 수정                → 커밋한 사람의 메일로 가른다
   git log HEAD~1..HEAD --format='%h %ce' -- docs/guide docs/chapters
   그 메일이 이 장비의 git config user.email 과 같을 때만 잡는다
```

★ 상수를 코드에 안 박았다 — 메일은 `git config user.email` 이 준다 (S14).
