# 0b — KB 잠금 · ★ **`save_listing_pii` 는 범인이 아니다**

KB 를 실제로 돌리며(`--narrow --detail 10 --bursts 1`) `save_listing_pii` 를 계측했습니다.

## ① locked 가 난 그 시각에 무엇이 함께 돌았나

```
한 회차 297.2초 동안 — ★ 재판정이 돌던 초 0 / 298
```

★ 이번 회차에는 **아무것도 함께 안 돌았고 locked 도 안 났습니다.**

★ 다만 **함께 돌 수 있는 것 셋**을 찾았습니다 (타이머가 셋입니다) —

```
carwatch-daily          13:00           수집 열 + 재판정
carwatch-recalc-catchup 01,05,09,13,17,21시   ★ recalc_catchup.py — 재판정을 넣는다
carwatch-check-light    02,06,10,14,18,22시   light_check.py
```

★★ **`recalc-catchup` 이 네 시간마다 재판정을 넣습니다.** KB 한 회차가 297초이고
재판정 한 판이 12~13분이라, **13시·17시·21시에 KB 를 돌리면 겹칩니다.**
★ 08-29 에 KB 가 죽은 것도 이 무늬로 보입니다 — 다만 **그 시각의 기록이 없어
단정하지 않습니다.** 다음에 나면 그 자리에서 잡도록 계측을 남겨 둡니다.

## ② `save_listing_pii` 가 한 회차에 몇 번 · 한 번이 몇 ms 쥐나

```

```

★★ **한 번에 0.1ms 입니다.** 267번 다 합쳐도 11ms 입니다 —
297초 회차의 **0.004%** 입니다. **이것이 잠금을 만들 수 없습니다.**

## ③ 그 트랜잭션이 넣기 걸음 커밋 안에 있나 밖에 있나

