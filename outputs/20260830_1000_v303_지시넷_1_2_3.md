## 3 — K카 `resvYn` → `sales_status`

| 파일 · 줄 | 무엇 |
|---|---|
| `parse/kcar/mapping.py:205` | `resvYn` 을 `sales_status` 에 **사이트 말 그대로** |
| `config/labels.json` | `SALES_STATUS_SOLD` — **새 표** (낱말 → 우리 말) |
| `report/screens/build.py:993` | `_sold_words()` · `_order_sold()` — 코드에 박힌 낱말을 뺐다 |

### ★ 두 겹이었습니다

① **파서가 안 읽었다** — `resvYn` 을 아예 안 봤습니다.
② **화면이 낱말을 코드에 박고 있었다** — `('CONTRACT','RESERVED')` 뿐이라
   `resvYn=Y` 를 넣어도 여전히 「판매 중」으로 섰을 것입니다.

둘 다 고쳤습니다. 낱말은 **`config/labels.json` 이 정본**이고, 근거로
`docs/chapters/11-store/a-key.md` 08-29 절(「`Y` 118 / `N` 369 · **예약 = 계약 중**」)을
그 자리에 적었습니다. **개발측이 낱말을 지어 넣지 않았습니다** (규칙 2).

### 몇 → 몇 — ★ 눌러서 쟀다

```
파서가 내는 값 (재고목록 487건에 걸어)
  resvYn=N  369
  resvYn=Y  118      ← ★ 가이드 실측과 정확히 같다

DB (우리 대상만 넣으므로 105건)
  resvYn=N  83
  resvYn=Y  22

우리 대상이면서 화면 범위 안 — 5건.  다섯 다 —
  매물 11351 · sales_status=resvYn=Y → sold=True · 딱지=예약중
  매물 11419 · 〃
  매물 11511 · 〃
  매물 13627 · 〃
  매물 13629 · 〃
```

| | 전 | 후 |
|---|--:|--:|
| `resvYn` 을 읽나 | **아니오** | **예** |
| `sales_status` 가 붙은 K카 매물 | **0** | **105** (예약 22) |
| 화면이 예약을 아나 | **모른다** (「판매 중」) | **안다** (흐리게·맨 뒤·「예약중」) |
| 낱말이 어디 있나 | **코드에 박힘** | **`config/labels.json`** |
