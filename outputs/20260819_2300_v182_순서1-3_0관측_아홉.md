## 5. `V1-26` 신설 — ★ 번호가 겹칩니다

지시는 `V1-24` 라 하셨는데 **그 번호는 개정 327 이 이미 쓰고 있습니다.**

```

inbox/ANSWER_registry32.md                 V1-24  판정 축이 쓰는 경로 중 전건 null 을 센다 (신설)
```

★ 전에 제가 규격의 번호를 뺏어 사고가 났습니다 (v144). **이번엔 안 뺏었습니다.**
비어 있던 **`V1-26`** 으로 만들고 검사 설명에 그 사정을 적었습니다.
**번호를 정해 주시면 그대로 옮기겠습니다.**

### 무엇을 재나

```
① 축 전건이 「확인 안 됨」인가            ← 이것이 fatal 이다
② 파서가 읽는 경로 중 어디서도 값이 안 오는 것  ← 목록으로 낸다
```

★ **②만으로 fatal 을 내지 않았습니다.** 지시는 「0이면 fatal」이지만
실제로 재 보니 이렇게 나옵니다.

```
floodDate         0 / 7,980   침수가 일어난 매물에만 채워지는 날짜다
robberDate        0 / 7,980   도난이 일어난 매물에만
floodPartLossCnt  0 / 7,980   ★ 이것만 진짜로 안 온다
```

`floodDate` · `robberDate` 는 **사건이 없으면 전건 null 이 맞습니다.**
그것으로 fatal 을 내면 영영 붉은 채로 남습니다 — 거짓 경보는 검사가 아닙니다.
그래서 **①을 fatal 로, ②는 매번 목록으로** 냅니다 (4시간 점검이 그대로 봅니다).
★ **이 셋을 「사건이 없어서 빈 것」으로 볼지 정해 주십시오.**

★ 4시간 점검(`light_check`)은 `check_all` 을 통째로 돌립니다 — 등록만 하면 함께 돕니다.
