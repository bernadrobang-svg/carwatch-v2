# 2. 판단 — 쓴다. 다만 `pending` 으로만

## 왜 쓰는가

```
지금 facet 을 못 받으면 S3 가 영원히 막힌다
목록으로 pending 을 만들면 파이프라인이 끝까지 돈다
```

## 왜 `confirmed` 로 올리지 않는가

```
facet   그 사이트가 인정하는 값의 전체 집합
목록    지금 등록된 매물이 가진 값만
```

```
color_ext  facet 30종 (가정) · 목록 관측 23종
→ 7종이 빠진다.  나중에 그 색 매물이 뜨면 미분류가 된다
```

**「전체 집합을 봤다」가 아니기 때문입니다.**

# 3. 규격 — 개정 266

```
필수   facet 이 있으면 facet 이 정본이다
필수   facet 이 없으면 목록에서 관측한 값으로 pending 을 만든다
필수   출처를 남긴다 — source='list' · 'facet'
       화면에 「facet 없이 목록에서 관측한 것입니다」를 낸다
필수   나중에 facet 을 받으면 목록 관측분과 대조한다
       facet 에만 있는 값  →  새 pending
       목록에만 있는 값     →  ★ 확인 필요.  facet 에 없는 값이 왜 매물에 있나
금지   목록 관측만으로 confirmed 를 만드는 것
검산   V3-37  목록 관측분의 source 가 'list' 인가
       V3-38  facet 수신 후 목록 관측분과 대조하는가
```

**`V3-38` 의 「목록에만 있는 값」이 중요합니다.** 그건 엔카가 facet 에 안 넣은 값이거나, 우리가 잘못 읽은 것입니다. 둘 다 알아야 합니다.
