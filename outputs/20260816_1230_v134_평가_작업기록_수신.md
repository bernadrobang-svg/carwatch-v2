# 2. 특히 잘한 것 4가지

## ① 규격의 뜻을 정확히 읽었습니다

```
규격이 요구하는 것은 「상한을 넘지 않는다」이지 「쿼리를 줄여라」가 아니다
그래서 의미가 같은 중복만 없앴다.  화면이 내는 값은 하나도 바뀌지 않았다
```

**「고치라니까 최대한 줄이자」로 가지 않았습니다.**

## ② 여유를 남겼습니다

```
① 만으로도 통과지만 상한에 딱 붙어 여유가 0 이라 ② 를 더했다
21 → 20 → 17
```

**「통과했으니 끝」이 아니라 「다시 터질 자리」를 봤습니다.**

## ③ 문서를 덮기 전에 `diff` 를 봤습니다

```
docs/ 는 정본이라 덮어쓰기 전에 셋 다 diff -u 로 대조했다
세 파일 모두 순증뿐이고 삭제·수정은 0줄이다
```

**개정 238「지시서는 개발측이 고치지 않는다」를 스스로 확인했습니다.**

## ④ ★ 결과 변동의 원인을 끝까지 팠습니다

**이게 가장 큽니다.**

```
같은 코드인데 01:20 과 12:15 의 시험 결과가 달랐습니다
```

**Claude Code 가 네 단계로 원인을 확정했습니다.**

```
1  carwatch.db 에 status='queued' 인 recalc_job 1건
2  store/admin.py:83  JOB_OPEN = ("queued","running")  — queued 도 잠금
3  test_spec_ui 가 test_integration.py:129 로 운영 DB 를 복사해 돈다
4  관리 화면이 전부 409 로 잠기고 config_change 0행 → 첨자에서 TypeError
```

**행동 증거까지 붙였습니다.**

```
S5-16 이  01:20 「400 · 아직 저장할 수 없습니다」
         12:15 「409 · 지금은 바꿀 수 없습니다」
```

**「환경 탓이겠지」로 넘기지 않고 증거로 확정했습니다.**
