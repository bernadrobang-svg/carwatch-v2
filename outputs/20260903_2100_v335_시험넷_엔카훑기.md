### ② 시험 셋을 규격에 맞췄다 — `tests/test_score.py`

배점이 개정 1084/1085 로 바뀌었는데 시험이 옛 숫자를 들고 있었다.
**코드가 아니라 시험이 낡은 것**이라 시험을 고쳤다.

| 무엇 | 옛 시험 | 새 규격 |
|---|---|---|
| 기피색 | `== 0` | `기피 < 기본 < 선호` (기피 0→7, 명령서 7번) |
| 예산 | 기준가 = 한계 | **100% = 만점**(`_b100 == 95`) |
| 트림 | `59` 박아 둠 | `comp(taste.trim) <= comp(value.origin)` · `_span > 0` |

숫자를 박지 않고 **관계로** 적었다 — 배점이 또 바뀌어도 안 죽는다.

### ③ 판을 안 죽인다 — `tests/test_store.py`

### ④ 다른 조건으로 견주고 있었다 — `tests/test_screens.py`

```

```

거르개를 의심해 **직접 셌다** —

```
거르개 없음 6행 · taste.size unknown 6행     ← 똑같다.  거르개는 옳다
씨앗 taste.size  행 12 · excluded 12 · value NULL 12
```

까닭은 시험 쪽이었다. 윗줄에서 `rows` 를 `lease=True` 로 잡아 놓고
`na` 만 그것을 빼고 견줬다 — **바로 위 시험이 그 주의를 이미 적어 뒀는데**
(「한쪽만 리스를 빼면 1+0 != 3 이 된다」) 새로 더한 줄이 그것을 안 지켰다.

## 5. 명령서 4번 — 엔카가 왜 두 달에 3건만 죽였나 (`S46-234`)

`sweep_done_ratio = 0.98` 을 앞 회차에 넣었는데 **검사가 그대로 fatal 이다.**
까닭을 쟀다.

```
S46-234  매물 최다 encar 이 15,020건인데 gone 3건 — 다른 사이트는 최대 198건
```

`run.py collect --only S4` 를 돌려도 훑기 줄이 안 나왔다. 원문 날짜를 봤다 —

```
raw_response  encar · list  최종 2026-08-31   (오늘 09-02)
```

**S4 는 그날 받은 봉투만 훑는다.** 오늘 것이 없어 훑기가 아예 안 돈다.
그래서 전량 수집을 돌리는 대신 **08-31 봉투로 되짚어** 고침의 값을 쟀다.

```
잣대 옛(전량)   끝난 질의 11/25 · 훑는 매물 1,433
잣대 0.98      끝난 질의 21/25 · 훑는 매물 8,953
```

| | 옛 잣대 | `0.98` |
|---|--:|--:|
| 「끝까지 받았다」고 본 질의 | 11 / 25 | **21 / 25** |
| gone 을 매길 수 있는 매물 | 1,433 | **8,953** (6.2배) |

까닭이 확인됐다 — 스물다섯 질의 중 **열넷이 몇 건씩 모자라** 막혀 있었고,
그 질의가 건드린 차종이 통째로 빠져 15,020건 중 1,433건만 훑고 있었다.
받는 사이에 팔려 빠진 몇 건 때문이다(우리 잘못이 아니다).

★ **고침은 들어가 있고 값도 읽힌다**(`sweep_done_ratio: 0.98`).
  ★ 다만 **다음 실제 수집(S3)이 돌아야 화면 숫자가 바뀐다.**
  ★ 되짚기가 그때 1,433 → 8,953 이 될 것을 미리 보인다.
