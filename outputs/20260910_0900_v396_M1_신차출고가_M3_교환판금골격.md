## 2. M-1 — 신차출고가

### 2-1. 무엇이 문제였나

`price_origin_won` 은 **등급기준가**다 (엔카 `category.originPrice`). 옵션값이 빠져 있다.
`origin_total_won`(등급기준가 ＋ 옵션) 은 개정 301 부터 **셈은 있었는데 어디에도 안 담겼다** —
판정이 돌 때만 살아 있다가 사라졌다. 화면이 매번 다시 셌다.

### 2-2. 한 것

* `sql/ddl/02_core.sql` — `price_origin_total_won` · **`price_origin_total_src`** 두 칸
* `tools/fill_origin_total.py` — 채운다. 못 셈하면 **비운다** (금지 12)
* `report/screens/tabs.py` `_gv70_card` — 「값 / 신차출고가 / 잔가율 (감가율)」

### 2-3. ★ KB 가 신차가를 **스스로** 준다 — 우리가 셈하지 않아도 된다

KB 상세 원문에 이 줄이 있다.

```
var sellAmt = "2450";  var newcarPrice = "4863";
newcarPrice = parseInt(newcarPrice*1.1);
```

KB 가 그 값을 스스로 이렇게 설명한다 (`btnNewCarPriceTooltipClick`).

> **신차가격?** 차량의 최초 취득가격으로 **선택옵션, 프로모션, 부가세가 포함된 실 구매가격**입니다.

지시가 말한 **「신차정가가 아니라 신차출고가(옵션 포함)」** 와 **글자 그대로 같다.**
원문값은 부가세 뺀 값이고 화면이 ×1.1 해서 그린다 — 그래서 **×1.1 한 것**을 담았다.

**맞는지 견줬다** — 같은 차종에서 두 셈이 3% 안에서 만난다.

| 차종 | KB 신차가 중앙 | 엔카 셈(등급기준가＋옵션) 중앙 |
|---|--:|--:|
| G80_25T | 6,260만 (708대) | 6,447만 (2,101대) |

### 2-4. 못 채운 것 — 까닭별

| 까닭 | 건수 |
|---|--:|
| 등급기준가가 없다 (＝ 상세를 못 받았다 · B 과제) | 7,004 |
| 옵션을 모른다 | 724 |
| 옵션값이 모자라다 (코드값이 사전에 없다) | 77 |
| 신차가가 판매가보다 낮다 — **그 신차가를 안 믿는다** | 12 |

마지막 줄은 억지로 채우면 감가율이 음수가 된다. 담지 않았다.

**「6,061건이 비어 있다」와 우리 숫자가 다르다 — 분모를 밝힌다.**
우리가 재면 살아있는 매물 15,589 중 **7,817** 이 비어 있다 (채운 7,772).
다른 분모로 재면 — 등급기준가는 있는데 못 채운 것 **801** · 엔카만 보면 **1,858**.
6,061 과 맞는 분모를 못 찾았다. 어느 분모로 재신 것인지 알려 주시면 그 자로 다시 잰다
(★ 유리한 분모로 재지 않는다).

### 2-5. 남은 말 — 「잔가율」과 「감가율」

지시서가 두 이름을 **서로 반대로** 쓴다.
`78% 기준` 은 **잔가율**(값 ÷ 신차가)이고, `(1 − 값 ÷ 신차가) × 100` 은 **감가율**이다.
고르지 않고 **둘 다 냈다** — 화면에 「61.6% (감가 38.4%)」로 적는다.
어느 쪽을 정본으로 할지는 회차 문서로 확인을 받는다 (규칙 2).

## 3. M-3 — 교환 · 판금 · 골격

### 3-1. 자료는 이미 우리 안에 있었다

엔카 성능점검 원문 `outers[]` 가 자리마다 이렇게 준다.

```json
{"type": {"code": "P022", "title": "프론트 휀더(우)"},
 "statusTypes": [{"code": "X", "title": "교환(교체)"}],
 "attributes": ["RANK_ONE"]}
```

* 상태 — `X` 교환 · `W` 판금/용접 · `WC` 용접·절단 · `T` 손상
* 등급 — `RANK_ONE`·`RANK_TWO` 는 **외판**, `RANK_A`·`RANK_B`·`RANK_C` 는 **골격**

600건에서 센 것: 상태 X 964 · W 460 · WC 16 · T 3 / 등급 ONE 987 · TWO 210 · A 150 · B 79 · C 1.
`config/dictionaries/panel_rank.json` 에 담았다 — **값을 코드에 안 박는다** (S14).

### 3-2. 한 것

* 칸 넷 — `accident_swap_cnt` · `accident_weld_cnt` · `accident_frame_cnt` · `accident_parts_json`
* `tools/fill_accident_parts.py` — 자리 목록을 가른다
* 추천 4 — 「교환 3곳 (리어 도어(좌) · 후드 · 프론트 도어(좌)) / 판금 0곳 / **골격 무사고**」
* 추천 3 — 조건에 「**골격 무사고 (단순교환까지)**」를 더했다 (O · X · 미조회)

실제 화면 (G80_25T 실측):

```
교환 6곳 (리어 도어(우) · 프론트 휀더(우) · 후드)[warn]
판금 4곳 (프론트 사이드 멤버(우) · 쿼터 패널(우) · 프론트 도어(우))
★ 골격 2곳 (프론트 사이드 멤버(우) · 인사이드 패널(우))[no]
내차 5회 / 2,059만 · 상대차 3회 / 609만
→ 「골격이 2곳 상했습니다 — 마스터 기준에서 벗어납니다 ·
    교환이 6곳입니다 — 4곳 이상이면 사고 1,000만 이상으로 봅니다」
```

### 3-3. ★ 「교환 4곳 이상 = 사고 1,000만 이상」 — 우리 자료로 재 봤다

교환 곳수와 **보험 사고금액**(내차＋상대차)이 둘 다 있는 5,602대.

| 교환 | 대수 | 사고금액 중앙 | 1,000만 넘는 비율 |
|--:|--:|--:|--:|
| 0 | 4,622 | 0만 | 3% |
| 1 | 547 | 444만 | 22% |
| 2 | 236 | 638만 | 33% |
| 3 | 106 | 860만 | 46% |
| **4** | 50 | **1,288만** | **60%** |
| 5 | 19 | 1,248만 | 58% |
| 6+ | 22 | 1,439만 | 59% |

**중앙값이 1,000만을 넘는 첫 자리가 정확히 교환 4곳이다.**
마스터 기준과 우리 실측이 같은 자리에서 만난다. 표를 사전에 적어 두었다.

### 3-4. 골격은 **자르고**, 미조회는 **안 자른다**

`_gv70_card` 의 후보 잣대에 「골격이 상했으면 후보가 아니다」를 걸었다.
처음엔 **미조회도 잘랐다** — 그랬더니 추천 4 가 **0대**가 됐다.
「못 찾았다」와 「없다」는 다르다 (가이드 09-09). 되돌렸다.
미조회는 남기고 **화면에 「골격 미조회」로 적는다.**

### 3-5. 지나가다 잡은 것 — 「미조회」를 **초록**으로 칠하고 있었다

사고 칸이 `"ok" if not my_cnt else ""` 였다. `my_cnt` 가 `None`(미조회)이면
`not None` 이 참이라 **초록(무사고)** 이 됐다.
**모르는 것을 「괜찮다」로 칠한 것**이다 (금지 12).
`my_cnt == 0` 일 때만 초록, `None` 이면 붉게 고쳤다.

## 6. 막힌 것 · 판단이 필요한 것

1. **추천 4(GV70_25T) 는 아직 사고가 전부 「미조회」다.**
   우리가 가진 GV70 성능점검 141장은 **전부 GV70_EV** 것이다.
   GV70_25T 는 **한 장도 없다.** 엔카 성능점검은 서버에서 407 이고,
   KB 는 GV70 상세를 **0건** 갖고 있다 (KB 상세 768장 중 GV70 0장).
   → **B(대상 차종 상세)** 가 풀려야 이 칸이 산다.

   **오늘(09-10) 다시 두드려 봤다** — 「막혔다」를 증거 없이 적지 않는다.

   ```
   GET https://api.encar.com/v1/readside/inspection/vehicle/42656864
   → HTTP 407 Proxy Authentication Required
   ```

   엔카 **상세**에는 자리 목록이 없다 — `condition` 에 
   `{"accident": {"recordView": true}, "inspection": {"formats": ["TABLE"]}}`
   같은 **깃발만** 있다. 성능점검 창구를 열지 않으면 못 받는다.

   ★ 추천 3 의 「다 맞는 차」는 지금 **20대**다. 그중 골격을 아는 것은 **1대**뿐이다
   (원문에서 되찾은 것). 나머지 19대는 성능점검 **19번**이면 끝난다 —
   `config/endpoints.json` 이 「후보가 몇 대로 좁혀진 뒤 그때 다시 정한다」고 적어 두었다.
   **지금이 그때다.** 어떻게 받을지 지시를 받는다 (마스터 회선은 안 쓴다 — 09-07).

2. **KB 성능점검 원문 168장**에도 교환·판금 낱말이 있다.
   다만 정부 표준 서식 HTML 이라 파서가 따로 필요하고,
   그 168장은 G80_25T 145 · GLC 4 뿐이라 **GV70 에는 안 닿는다.** 다음 회차로 미룬다.

3. **잔가율 · 감가율** 이름 — 위 2-5.

4. 감가율 잣대(`depreciation_max_pct`)는 **잔가율** 값으로 적혀 있다.
   지금은 「잔가율이 잣대 이하면 후보」로 읽고 있다. 맞는지 확인을 받는다.
