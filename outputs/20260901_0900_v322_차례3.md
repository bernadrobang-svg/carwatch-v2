### ★ 남은 −20 은 왜 못 닫나

★ `V2-01` 은 「**마지막 detail 봉투가 `ok`**」와 「**CORE 가 `detail_status='ok'`**」를 견줍니다.

```
KB 23건 —  봉투: HTTP 200 · status 'ok'   ← 받기는 받았다.  참이다
           속:   「없는 차」               → detail_status 'not_found'.  참이다
```

★ `save_site_raw` 는 ★ `status` 를 ★ **늘 `"ok"` 로 박습니다** (`store/raw.py:443`).
★ 그런데 `raw_response.status` 에는 ★ `not_found` 값이 ★ **이미 42,690행** 쓰이고 있습니다 —
곧 「없다고 답한 봉투」를 가리키는 낱말이 이미 있습니다.

★★ **고칠 길이 둘입니다. 제가 안 고릅니다 (규칙 2)** —
```
ⓐ 봉투 status 를 속에 맞춘다 — 「200 인데 없는 차」면 not_found 로 적는다
   ★ 다만 이미 쌓인 152,426행의 뜻이 바뀐다
ⓑ V2-01 이 「not_found 로 답한 봉투」를 빼고 센다
   ★ 검사를 무르게 하는 것이 아니다 — 「받았다」와 「있다」를 가르는 것이다
```
