## 3. 무엇을 했나 · 왜 그렇게 했나

```
config/admin.json
  min_secret_length  8  →  1
  login_fail_limit  10  →  0   (0 이면 잠그지 않는다)
  login_probe_tries      10    (검사가 「안 잠긴다」를 확인할 때 두드리는 수)
```

`store/admin.py`

```
if _limit and _recent_failures(...) >= _limit:      ← 0 이면 건너뛴다
```

★ **시도 기록은 그대로 남깁니다.**  기록을 지우는 것은 되돌릴 수 없습니다.
「잠그지 않는다」와 「안 남긴다」는 다릅니다.

---

## 4. ★ 안 한 것 — 일부러 남겼습니다

지시서는 「감사 · 세션 만료」도 지금 안 한다고 했습니다.  **안 껐습니다.**

| 항목 | 했나 | 왜 |
|---|---|---|
| 비밀번호 최소 길이 | **껐다** | 마스터가 막혀 있었습니다 |
| 로그인 잠금 (rate limit) | **껐다** | 같음 |
| 감사 기록 (`auth_login_attempt`) | **안 껐다** | ★ 기록은 되돌릴 수 없습니다. 끄면 그 동안의 일을 영영 모릅니다 |
| 세션 만료 12시간 | **안 껐다** | 끄는 이득이 없습니다 — 마스터가 막힌 적이 없습니다 |
| 2단계 인증 | 원래 없음 | — |
| HTTPS · 쿠키 Secure · 해시 미로그 | 그대로 | ★ 「되돌릴 수 없는 것」 목록 그대로 |

★ 둘을 안 끈 것이 지시와 어긋나면 말씀해 주십시오.  바로 끄겠습니다.

## 5. 검사 둘이 「잠긴다」를 못박고 있었습니다

```
V10-20   연속 로그인 실패 상한을 넘으면 거부됨      ← 실패
I-11     로그인 시도 상한                        ← 실패
통합 69  /login 11회 실패                        ← 실패
```

셋 다 **「잠긴다」를 기대값으로 박아** 두어 규격을 못 따랐습니다.

```
고침   config 를 그대로 따르게 했다
      상한이 0 이면 「안 잠긴다」가 통과다
      V10-20 제목도 「로그인 실패 상한이 config 대로 돎」으로
```

★ **검사가 규격을 앞질러 박혀 있으면 규격을 바꿀 수 없습니다.**
오늘 세 번째로 겪은 것입니다 (V3-64 · V11-71 · 이번).
