## 3. 무엇을 했나 · 왜

### ㉮ 헤이딜러 18건 — 「상세를 받았다」가 거짓이었다

풀리지 않은 18건의 원문을 열었다. **HTTP 200 · JSON dict** 인데 본문이 —

```
{"code":null,"message":null,
 "toast":{"message":"서버 오류가 발생했습니다.\n계속 오류가 발생하면 …"},
 "popup":null,"toast_message":"서버 오류가 발생했습니다.…"}
```

**198바이트짜리 오류 안내**다. 차 내용이 한 글자도 없다.
그것이 `raw_response.status='ok'` 로 남아 **상세로 세어졌다.**

★ 상세가 99가 아니라 **81** 이었다. 「파싱이 18건 밀렸다」가 아니라
**「상세가 18건 부풀었다」**가 참이다.

### ㉯ 뿌리 — 수집기가 규격의 관문을 안 거친다

`tools/collect_heydealer.py:171` 이 이렇게만 걸렀다:

```python
if code != 200 or not isinstance(body, dict):
```

규격의 관문은 `collect/fetcher.py:104 verify_shape()` 다 (2장 STEP 18
「저장 직전에 건다」). `adapters/heydealer.py:37` 의
`required_keys=["hash_id","detail_info"]` 를 봐야 하는데 **안 봤다.**

**고친 곳**

| 파일 | 줄 | 무엇 |
|---|--:|---|
| `tools/collect_heydealer.py` | 30-35 | `schema` 를 들여온다 |
| `tools/collect_heydealer.py` | 167-186 | ★ 「이미 받았나」에서 **껍데기를 안 센다** — 있어도 다시 받는다 |
| `tools/collect_heydealer.py` | 195-210 | ★ 저장 직전에 `required_keys` 를 건다 · 누락 열쇠를 찍는다 |
| `tools/mark_shell_raw.py` | 새 파일 | ★ 이미 들어온 껍데기의 **딱지를 되돌린다** |

★ `mark_shell_raw.py` 는 **원문(`body`)을 안 지운다** — `status` 만 `error` 로 바꾼다.
★ HTML 창구(BMW·현대인증·K카·보배드림·KB)는 **건드리지 않는다** — 열쇠로 못 잰다.

### ㉰ 전 사이트를 훑었다 — 껍데기는 헤이딜러뿐이다

```
  encar            껍데기     0건  (열쇠 ['category', 'manage'])
  kcar             껍데기     0건  (열쇠 ['data'])
  kia_cpo          껍데기     0건  (열쇠 ['id', 'car'])

★ 합계 껍데기 85건 — 딱지를 고쳤다
```

85건 전부를 눈으로 봤다 — **전부 같은 198바이트 오류 안내**였다.

### ㉱ 그러다 내가 재는 자리를 틀렸다는 것을 찾았다

딱지를 고치니 헤이딜러 상세가 **99 → 14** 로 떨어졌다. 껍데기는 85건인데
상세가 85건 넘게 빠진 것이 이상해 다시 봤다.

★ **헤이딜러의 진짜 상세는 `raw/heydealer/detail/` 파일에 있다.**
09-01 마스터 지시(「받기 걸음은 파일만 쓴다 · DB 를 안 연다」·`S46-204`)대로
수집기가 파일로 옮겨 갔고, `raw_response` 는 옛 사본이 남은 것이다.

→ 재는 잣대를 **`원문파일 ∪ raw_response(ok)`** 로 바꿨다.
곧 「받았다」의 참값은 **파일이 먼저**다.

## 5. 못 한 것 · 판단이 필요한 것

### ㉮ ★ 가이드께 — 리본카·볼보 상세는 **HTML 인데 규격이 `object`** 다

```
  reborncar      원문 322,231B  <!DOCTYPE html> …
  volvo_selekt   원문  54,255B  <!DOCTYPE html> …
```

두 곳의 `EndpointSpec.root_type` 이 `html` 이 아니라 `required_keys` 로 재면
**전건이 껍데기로 보인다.** 파싱은 잘 되고 있으므로 **규격 쪽 표기 문제**다.
규칙 2 대로 `docs/` 를 안 고쳤다 — **`root_type="html"` 로 고쳐 주시기를 청한다.**

### ㉯ ★ 「상세를 받았다」를 어디서 세는가 — 정본이 필요하다

지금 두 자리가 있다 — **원문 파일**(09-01 규격)과 **`raw_response`**(옛 사본).
사이트마다 어느 쪽에 있는지가 갈려(엔카·현대인증은 DB 만 · 리본카는 파일이 더 적다)
**같은 물음에 두 답이 나온다.** 이번 「상세 99 대 81」이 그것에서 났다.

의견 — **원문 파일이 정본**이고 `raw_response` 는 옮겨 가는 중의 사본으로 본다.
`S46-204`(받기가 파일에 쓰는가)가 이미 그 방향이다. 정본을 못 박아 주시면
`S46-26x` 으로 「두 자리의 수가 다르면 실패」를 세우겠다.
