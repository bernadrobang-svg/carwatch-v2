## 2. ★ `/fetch` 를 **실제 브라우저로 눌러** 한 바퀴를 돌렸습니다

「선다」가 아니라 **받는가**를 쟀습니다. 로그인해 크로미움으로 눌렀습니다.

```
큐     /fetch/queue?site=encar&step=2&n=1
       → https://api.encar.com/v1/readside/vehicle/39556892
받음   ★ 2번째 시도에 http 200 · 6,890B
올림   /fetch/put → {"status": "ok", "bytes": 6890}
파일   raw/encar/detail/2026-09-06/39556892.json  origin=browser · status=ok
DB     detail_status  →  ok
```

★ **이 자료는 진짜입니다** — 지우지 않았습니다. (v388 의 시험 자료는 가짜여서 지웠습니다.)

### ★ 왜 「2번째 시도」였나 — 제 크로미움이 **서버 위**에 있습니다

```
1번째   http 0    ← fetch 가 던졌다
2번째   http 200
```

`http 0` 의 정체를 갈랐습니다:

```
엔카 응답 머리 (Origin 을 붙여 확인)
  access-control-allow-origin: *
  access-control-allow-credentials: true
```

★ **CORS 는 열려 있습니다.** 곧 `http 0` 은 CORS 가 아니라
★ **서버 IP 가 받은 407** 입니다 — 407 에는 CORS 머리가 없어 `fetch` 가 던집니다.

★ **마스터 폰은 IP 가 열려 있으니 첫 번째에 200 이 옵니다.**
★ 제가 서버에서 그것을 증명할 수는 없습니다 — 여기는 막힌 회선입니다.
★ 다만 ★ **막힌 회선에서도 한 바퀴가 돌았으니 얼개는 맞습니다.**
