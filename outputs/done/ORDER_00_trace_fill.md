# 추적표를 채워라 — 다른 일보다 먼저

**★ 이것만 한다. 끝날 때까지 다른 것을 하지 않는다.**
**★ 세는 것이 아니라 채우는 것이다. 지난번에 세기만 했다.**

---

# 0. 왜 이것이 먼저인가

```
지금   요구 865건 중 상태 ○ 538건 (62%)
       ★ 그런데 소스 칸은 16건 (1%) 만 찼다
       ★ 「어디에 있는지 모르는데 됐다」가 538건이다
```

**★ 무엇이 빠졌고 무엇이 모자란지를 알 수 없다. 그것부터 안다.**

---

# 1. 소스 칸 — 849개를 채운다

```
필수   R 하나마다 「어느 파일 · 어느 함수」를 적는다
       예   `analyze/axis/option.py::score_option`
            `web/views.py::view_listings`
            `validate/v11_web.py::V11_100`

찾는 법 — 순서대로
  ① docs/MAPPING.md 로 장 → 디렉터리
  ② docs/SOURCE.md 로 파일 → 무엇이 어디에
  ③ ★ 그래도 못 찾으면 코드를 직접 grep 한다
     요구 문구의 낱말로 — 「시세」 「렌트」 「분모」 「팝업」
     검사 번호로 — V11-100 이 있으면 그 근처가 그 R 이다
  ④ 그래도 없으면 그 R 은 미구현이다

필수   ★ 못 찾은 R 은 소스 칸에 「미구현」이라 적는다.  비워 두지 않는다
필수   ★ 그 R 의 상태를 ✗ 로 내린다 (S38)
       「어디에 있는지 모르는데 됐다」는 성립하지 않는다
```

---

# 2. 화면 칸 — 748개를 채운다

```
필수   R 하나마다 「어느 화면 · 어느 자리」를 적는다
       예   `/listings` 10열 · `/why` ② · `/admin/dict`

찾는 법
  ① web/views.py 의 @app.route 를 전부 뽑아 표로 만든다
  ② 템플릿 이름 → 화면 이름
  ③ 그 화면 안에서 어느 절인지

필수   ★ 화면이 필요 없는 R 은 「해당 없음」이라 적는다
       예   계층 규칙 · 이름 규칙 · DB 제약 · 검사 설계
       ★ 비워 두는 것과 다르다
필수   ★ 화면이 있어야 하는데 없으면 「화면 없음」 + 상태 ◐ (S27)
```

---

# 3. 검사 칸 — 678개를 채운다

```
필수   R 하나마다 검사 번호를 적는다 — V11-100 · S28-1
필수   ★ CHECKS.md 로 잇는다.  없으면 「검사 없음」
필수   ★ S16 이 찾은 42건 — 규격에 있는데 코드에 없는 검사
       그 R 들의 검사 칸에 「검사 없음(규격에만)」이라 적는다
       ★ 그것이 만들 목록이다
```

---

# 4. 다 채운 뒤 — 상태를 다시 매긴다

```
S38 대로
  소스 「미구현」        →  ✗
  화면 「화면 없음」      →  ◐
  검사 「검사 없음」      →  ◐
  넷이 다 차면          →  ○  (테스트는 비어도 된다)
```

# 6. 그리고 이 셋을 목록으로

```
① 소스가 없는 R — 미구현 목록
   ★ 이것이 「빠진 것」이다
② 화면이 없는 R — 못 쓰는 기능 목록
   ★ 이것이 「모자란 것」이다
③ 검사가 없는 R — 지킨다고 믿을 근거가 없는 것
   ★ S16 의 42건이 여기 들어간다
```

**★ 마스터가 보실 것은 이 셋입니다.**
