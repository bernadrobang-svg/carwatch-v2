## 2. ★ 「사이트에 접근할 수 없음」의 원인을 찾았습니다 — 제 잘못입니다

**`null` 이 아니라 서비스가 죽어 있었습니다.**

```
systemctl is-active carwatch     activating   ← 재시작 루프
ss -tlnp | grep 8765             127.0.0.1:8765  users:(("python3.11",pid=120091))
                                 ★ 이 pid 가 제 개발 서버다
```

`carwatch.service` 는 `--host 0.0.0.0 --port 8765` 로 뜬다. 그런데 **제가 화면을
확인하려고 띄운 개발 서버가 그 포트를 쥐고 있었다.** 개발 서버는
`config/web.json` 의 `host: 127.0.0.1` 을 쓰므로 **밖에서는 아무것도 안 보인다.**

```
제 개발 서버를 내림
systemctl is-active carwatch     active
ss -tlnp | grep 8765             0.0.0.0:8765
curl http://43.201.16.78:8765/listings          200
curl http://43.201.16.78.sslip.io:8765/listings 200
```

**마스터가 보신 「사이트에 접근할 수 없음」은 이것입니다.**
「null 에 접근할 수 없습니다」는 그 화면의 다른 줄이거나 다른 탭으로 보입니다 —
아래 3절대로 전수 조사했으나 서버가 내는 HTML 에는 `null` 이 한 번도 없습니다.

**재발 방지를 `CLAUDE.md` 에 못 박았다.**

```
금지   run.py web 을 8765 로 띄우는 것.  시험은 --port 8799 로
필수   코드를 고쳤으면 sudo systemctl restart carwatch
확인   systemctl is-active · ss -tlnp | grep 8765 가 0.0.0.0 인가
```

## 3. `null` 전수 조사 — 서버가 내는 HTML 에는 **0회**

가이드 물음 4의 답부터.

```
web/template.py:258
  return html.escape("" if raw is None else str(raw))

★ None 은 빈 문자로 나온다.  'None' 도 'null' 도 안 찍는다
```

전 화면(관리자 권한 29화면)을 실제로 렌더해 `href`·`src`·`action` 을 전수 검사했다.

```
href="null" · src="null" · href="None"        0곳
href=""  ·  src=""                            0곳
본문의 null (JS 제외)                          0회
```

**대신 다른 결함이 나왔다 — 빈 조건으로 가는 링크 5곳.**

```
/listings  href="/listings?dealer="     × 5
```

딜러 상호가 없는 매물에서 링크가 만들어졌다. 누르면 조건이 안 걸린 **전건**이 나온다.
「빈 링크」가 아니라 「링크 아님」이어야 한다는 규격 그대로다.

## 5. HTTPS — 앱 쪽은 마쳤고 서버 쪽은 마스터 차례다

### ⑤ 먼저 확인하라던 것 — 둘 다 https 200

```
https://www.encar.com/dc/dc_cardetailview.do?carid=42515780   200
https://ci.encar.com/carpicture01/pic3801/38016911_001.jpg    200
```

**혼합 콘텐츠 문제가 없다.** 엔카 원문 링크도 `https` 로 바꿨다 (config 한 줄).

### ④ 쿠키 Secure — 했다

```
web/server.py    X-Forwarded-Proto 를 req["proto"] 로 올린다
web/session.py   is_https(req) — 없으면 http 로 본다
web/views.py     로그인·로그아웃 쿠키에 secure=is_https(req)

실측   평문  s=x; HttpOnly; SameSite=Lax; Path=/; Max-Age=3600
      HTTPS s=x; HttpOnly; SameSite=Lax; Path=/; Max-Age=3600; Secure
```

★ 머리글이 없으면 **붙이지 않는다.** 평문인데 붙이면 쿠키가 아예 안 가서 로그인이 죽는다.

### ② Caddyfile — 준비만 해 뒀다

`deploy/Caddyfile` 에 넣었다. 세우는 순서도 파일 안에 적었다.

## 9. 못 한 것 · 막힌 것 · 판단이 필요한 것

### ① ★ HTTPS 는 마스터가 콘솔에서 하실 차례다

```
1  보안 그룹 carwatch-sg 에 80 · 443 을 연다        ← 마스터
2  Caddy 설치 (sudo dnf) · deploy/Caddyfile 을 /etc/caddy/ 로
3  carwatch.service 의 --host 를 127.0.0.1 로     ★ 2 를 마친 뒤에
4  보안 그룹에서 8765 를 닫는다                      ← 마스터
```

**★ 3을 먼저 하면 화면이 안 열린다.** 1이 끝나면 알려 주시면 2·3을 한다.
설치는 `sudo` 가 필요하므로 진행 전에 여쭙는다.

### ② 「null 에 접근할 수 없습니다」의 정확한 자리는 못 찾았다

서버가 내는 HTML 29화면에 `null` 이 0회다. 두 가지로 본다.

```

㉯ 다른 탭이나 브라우저 확장
```

**어느 화면에서 무엇을 누르셨는지 알면 확정할 수 있다.** `V11-72` 가 앞으로 막는다.
