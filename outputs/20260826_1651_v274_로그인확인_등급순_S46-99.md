## 2. ★ ① 로그인 — ★ 된다.  ★ 마스터께서 보신 것은 「틀린 비번」 화면이다

### 2-1. 자격을 받아 실제로 재 봤다

```
POST /login (master / 바른 비번 ＋ csrf)
  HTTP/2 ★ 303
  location: /
  set-cookie: cw_session=…; HttpOnly; SameSite=Lax; Path=/; Max-Age=43200; Secure
```

★ **303 과 `Set-Cookie` 가 정상으로 나온다.**

### 2-2. ★ 고친 뒤 `/watch` · `/admin` (마스터께서 적으라 하신 것)

| 화면 | 로그인 **앞** | ★ 로그인 **뒤** |
|---|--:|--:|
| `/` | 200 | **200** |
| `/listings` | 200 | **200** |
| `/track` | 200 | **200** |
| **`/watch`** | **403** | ★ **200** |
| **`/admin`** | **403** | ★ **200** |

★ **둘 다 200 이다.**

### 2-3. ★ 그러면 마스터께서 보신 「200 · 쿠키 없음」은 무엇이었나

네 가지를 갈라 재 봤다.

| 경우 | 응답 | `Set-Cookie` | 화면 글 |
|---|--:|:--:|---|
| **바른 비번** | ★ **303** | ★ **있다** | → `/` 로 보낸다 |
| ★ **틀린 비번** | **200** | **없다** | 「…맞지 않습니다」 |
| csrf 가 낡음 | 403 | 없다 | 「권한이…」 |
| csrf 가 없음 | 403 | 없다 | 「권한이…」 |

★★ **「200 · Set-Cookie 없음」은 ★ 비밀번호가 틀렸을 때의 화면이다.**
★ 자리를 안 내주는 결함이 아니라 **안 내주는 것이 맞는 자리**였다.

★ **짐작 하나를 보태 둔다** — `curl` 을 대화형 bash 에서 쓰시면
비밀번호 끝의 `!` 가 **셸 히스토리 확장**에 먹힌다. 작은따옴표로 감싸야 한다.
(이번에 나도 그것을 피해 작은따옴표로 보냈다.)

### 2-4. ★★ 그리고 알려야 할 것 — ★ 비밀번호가 public 저장소에 적혀 있다

```

```

★ **등급순인데 ★ 못 매긴 것이 맨 앞에 왔다.** 그것들은 순위가 없으니
「순위 없음」이 뜬 것이다 — ★ 「N위가 없다」의 정체다.

### 4-3. ★ 뿌리 둘 (실측)

```
① report/screens/build.py  "grade": "s.grade ASC"     ← ★ 알파벳순이다
   실측  SELECT g FROM (…'S'…NULL…'A'…) ORDER BY g ASC  →  [None, 'A', 'S']
   ★ 'S'(최고)가 ★ 'A'~'G' 뒤로 간다.  ★ 등급순인데 ★ 등급 차례가 아니었다

② ORDER_HEAD 가  CASE WHEN s.grade IN ('EXCLUDED','NO_GRADE','NOT_RATED','PENDING')
   ★ `s.grade IS NULL` 을 ★ 빠뜨렸다
   실측  판정 행이 아예 없는 매물 ★ 9,097건 (LEFT JOIN)
        SELECT CASE WHEN NULL IN (…) THEN 1 ELSE 0 END  →  ★ 0
   ★ 곧 「순위를 매기는 것」으로 세어지고 ★ ASC 에서 NULL 이 맨 앞이다
```
