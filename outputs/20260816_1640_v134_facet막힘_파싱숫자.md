## 3. 왜 그렇게 했나 (규격)

- 개정 260 · `V4-25` — `color_ext`·`color_int`·`fuel` 사전은 facet 에서 나온다
- 5장 `PRECEDES` — `S3 = (S1, S2)` · `S6 = (S5, S3)`. 순서를 건너뛰지 않는다
- 2장 STEP 23 · STEP 43 — facet 은 「사이트가 정의한 열거값」이다. `Count=0` 도 넣는다 —
  「그 값이 없다」가 아니라 「이 쿼리 범위에 없다」이기 때문이다
- 규칙 2 — 규격이 정한 원천(`AXIS_SOURCES`)을 내가 바꾸지 않는다

## 6. 못 한 것 · 막힌 것 · 판단이 필요한 것

### ① ★ facet 실패 사유가 필요하다 — 이것 하나면 뒤가 다 풀린다

**「facet 만」을 골라 ① 조회 → ③ 저장을 눌러 주십시오.**
실패하면 화면에 이렇게 뜹니다.

```
facet 이 N바이트 — 나눌 수 없습니다      ← 크기 문제
HTTP 407 / 403 / 429                  ← 사이트가 막은 것
저장 413 (N바이트)                     ← 상한 초과
```

**그 한 줄만 알려 주시면 됩니다.** 서버는 `/search/` 가 407 이라 직접 확인할 수 없습니다.

### ② ★ 규격 판단 — 목록 원문에 그 값들이 이미 다 있다

이번 파싱이 보여 준 것이다.

```
AXIS_SOURCES 가 정한 원천        실제로 받은 목록 원문에 있는 것
  fuel       ← facet            fuel_raw       5종
  color_ext  ← facet            color_ext_raw  23종
  color_int  ← facet            color_int_raw  10종
  trim       ← list 봉투         trim_badge     68종
```

**facet 없이도 이 사전들을 채울 수 있다.** 다만 둘은 뜻이 다르다.

```
facet   사이트가 정의한 열거값 전체.  Count=0 인 값도 준다 (STEP 43)
목록    이 쿼리 범위에 실제로 나타난 값만
```

규격이 facet 을 고른 이유가 STEP 43 에 적혀 있으므로 **내가 `AXIS_SOURCES` 를
바꾸지 않았다** (규칙 2). 판단이 필요하다.

```
A. facet 을 계속 기다린다            원칙대로.  ①의 사유를 받아 고친다
B. 목록 관측값으로 사전을 연다        7,631매물에서 나온 값이다.  「정의된 값」은
                                   아니지만 「이 범위에서 판정에 쓸 값」은 전부다
                                   facet 이 오면 그때 덮어쓴다
```

B 로 가면 **오늘 안에 S3 → S10 까지 돈다.** A 는 facet 한 건에 달려 있다.

### ③ 등록부 미분류 41종 — 목록 엔드포인트가 통째로 미등록이다

`meta_field_usage` 에 `endpoint='list'` 경로가 하나도 없다. S6a(등록부 동기화)가
아직 목록 원문을 본 적이 없어서다. `S4` 가 돌면 채워진다 — 이것도 `S3` 뒤다.
