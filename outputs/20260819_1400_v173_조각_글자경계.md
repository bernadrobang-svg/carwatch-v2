## 1. 무엇이 잘못이었나

```
★ 한글은 UTF-8 로 3바이트다.  바이트 수로만 자르면 글자 한가운데가 잘린다
★ 그 조각은 단독으로 유효한 UTF-8 이 아니다
★ 서버 parse_form 이 decode 하면 그 자리가 U+FFFD 로 바뀐다
★ 이어붙이면 길이·해시가 어긋난다 → 400
```

**옛 방식이 얼마나 깨지는지 실제로 세 봤습니다**

| 조각 크기 | 조각 수 | 깨진 조각 |
|--:|--:|--:|
| 7 | 258 | **258** |
| 11 | 164 | **164** |
| 32 | 57 | **57** |
| 100 | 19 | **18** |
| 257 | 8 | **8** |

**거의 전부입니다.**

## 2. 고친 것

### 3-1 절단점을 글자 경계로 (`V11-147`)

```javascript
function cut(bytes, off, room) {
  var end = Math.min(off + room, bytes.length);
  // 0b10xxxxxx 는 이어지는 바이트다.  글자 첫 바이트까지 뒤로 물린다
  while (end > off && end < bytes.length && (bytes[end] & 0xC0) === 0x80) {
    end -= 1;
  }
  return end;      // ★ end === off 면 room 이 너무 작다 — 멈춘다
}
```

★ **room 을 키워 해결하지 않았습니다** — `max_form_bytes` 상한은 그대로입니다.

### 3-2 조각마다 대조 (`V11-148`)

```
화면   partSig() 가 조각마다 chunk_part_len · chunk_part_hash 를 함께 보낸다
서버   _verify_part() 가 그 자리에서 대조한다
문구   「조각 3/9 가 깨졌습니다 — 길이가 다릅니다 (받은 20 · 보낸 999)」
      「조각 3/9 가 깨졌습니다 — 해시가 다릅니다 (받은 3edd68ed0cb4 · 보낸 0000…)」
      「조각 2/5 가 깨졌습니다 — 글자 가운데가 잘렸습니다」
★ 마지막에 몰아 터지면 어느 조각이 문제인지 알 수 없다
```

### 이어붙인 뒤에도 본다

```python
lost = text.count("�")
if lost:
    raise ValidationError(f"이어붙인 원문에 깨진 글자가 {lost}자 있습니다 — …")
```

★ **「400 이 안 났다」는 완료 근거가 아닙니다** (S42-2).

## 4. 검사 — 「코드에 있다」로 통과시키지 않았습니다

| 검사 | 무엇으로 실패시켰나 | 결과 |
|---|---|---|
| `V11-147` | 물리기(while)를 뺐다 | `room 7 조각 1 가 깨진다` |
| `V11-148` | 화면이 `chunk_part_hash` 를 안 보내게 했다 | `화면이 chunk_part_hash 를 안 보낸다` |
| `V11-148` | 해시 대조를 껐다 | `해시 가 달라도 통과한다` |

★ `V11-147` 은 **같은 규칙을 검사 안에서 실제로 돌립니다** — 다섯 크기로
잘라 이어붙이고, 조각마다 단독 UTF-8 인지, 이어붙인 것이 원문과 같은지 봅니다.
