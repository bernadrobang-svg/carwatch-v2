## 지시를 바꾸지 않는다

| 하지 말 것 | 왜 |
|---|---|
| 지시를 **무시하고** 다른 것을 한다 | 우선순위는 마스터가 정한다 |
| 지시를 **비틀어** 자기 방식으로 바꾼다 | 규격과 어긋나면 뒤에서 다시 깨진다 |
| 「기존에 이렇게 해왔으니 이렇게 하겠다」 | **기존 방식이 근거가 되지 않는다.** 지금 규격이 근거다 |
| 지시가 이상해서 **멈춘다** | 멈추지 않는다. 적고 진행한다 |

지시가 틀렸다고 판단되면 **그렇게 적고 지시대로 진행한다**.
되돌리는 비용이 진행하지 않는 비용보다 싸다.
바꿔야 한다고 생각하면 회차 문서에 **근거와 함께** 적는다. 말없이 바꾸지 않는다.

실제로 09-05 에 지시 순서가 잘못돼 있었다. 개발측이 그것을 적어 알려서 고쳤다.
그것이 옳은 방식이다. 말없이 무시했다면 원인을 못 찾았다.

## 진행 방식

멈추지 않는다. 질문이 있어도 멈추지 않는다.

| 상황 | 어떻게 |
|---|---|
| 막히는 것이 있다 | 그 항목만 남기고 **다음 항목으로 넘어간다** |
| 판단이 필요하다 | 가장 안전한 쪽으로 정하고 **회차 문서에 적는다** |
| 지시가 틀린 것 같다 | **그렇게 적고 그대로 진행한다**. 되돌리는 것이 진행 안 하는 것보다 싸다 |
| 다 끝냈다 | 회차 문서 하단에 「여쭐 것」과 「이견」을 적는다 |

허락을 기다리지 않는다. 앞 회차에서 질문하고 멈춘 일이 있었다.
질문은 회차 문서에 적고 작업은 끝까지 한다.
