없던 필터 6종을 만들고 값에 링크를 걸었다.

```

```

월납입은 **가격 상한으로 되짚어** SQL 로 건다 — `build_finance` 를 그대로 불러
이분법으로 역산한다 (`report/finance.py price_for_monthly`).
근사식을 새로 쓰면 화면의 숫자와 필터가 어긋난다.

### ③ ★ 그러다 쪽 넘김이 차종 필터를 흘리는 것을 찾았다

```
쪽 링크가 낸 것    /listings?target_key=G80_25T&page=2
필터가 읽는 이름    target
결과              2쪽으로 넘기면 차종 조건이 통째로 풀렸다
```

**어제 넣은 `V11-58`(쪽을 넘겨도 조건이 남는가)이 `grade` 만 봐서 놓쳤다.**
`grade` 는 필드 이름과 URL 이름이 같아서 우연히 통과했다.
필드 ↔ URL 이름 표(`CHIP_FIELDS_FULL`)를 만들어 한 곳에서만 정하게 했다.

### ④ ★★ S등급 매물에 「사고 있음」이 떠 있었다

```
/listings?grade=S  →  축 칸 title="사고 있음"      ← S등급인데
                                  "렌트 있음"
```

`result_axis.value` 는 **점수(0·5·10·15·20)** 인데
9장 STEP 91 값 표시 대조표는 `value=1 → 있음 / value=0 → 없음` 을 전제한다.
사양 축(HUD)은 「점수를 받았다 = 있다」라 맞지만,
**위험 축(사고·렌트·보험)은 「점수를 받았다 = 그 일이 없다」라 뜻이 정확히 뒤집힌다.**

`config/labels.json` 에 축별 문구를 두어 고쳤다.

```
사고 이력 양호 / 사고 이력 있음
렌트 이력 없음 / 렌트 이력 있음
보험 이력 양호 / 보험 이력 많음
```

같은 실수를 필터 단추에서도 할 뻔했다 — 「무사고」 단추를 `bucket=0` 으로
걸면 **사고 난 차만** 나온다. `bucket=1` 로 바로잡았다.

## 7. 못 한 것 · 막힌 것 · 판단이 필요한 것

### ① ★ 9장 STEP 91 값 표시 대조표가 점수 축과 안 맞는다 — 규격 확인 요청

```
대조표    value=1 → 있음 · value=0 → 없음
실제      result_axis.value = 0 · 5 · 10 · 15 · 20  (점수다)
```

`config/labels.json` 에 축별 문구를 두어 급한 뒤집힘은 막았지만,
**부분 점수(5·10·15)를 「양호」로 묶은 것은 정확하지 않다.**
v1 은 `AC1`·`AC4`·`I0` 처럼 **코드를 그대로** 냈다.

```
판단 요청   위험 축의 화면 문구를 어떻게 할 것인가
          ㉮ 지금처럼 양호/있음 2단 (부분 점수가 뭉개진다)
          ㉯ v1 처럼 코드를 낸다 (AC1 · AC4 · I0 · W1)   ← 개정 277 취지에 맞다
          ㉰ 점수를 그대로 낸다 (20/20 · 5/20)
```

㉯ 를 하려면 `result_axis` 에 코드가 없어 파싱까지 올라간다. **지시를 기다린다.**
