## J-④ 「현황 제목 깨짐」 — ★ 작업 중간 판을 캡처하신 것이다

```
가이드 캡처 08-22 01:01   수집 진행률 % — 요청 없습니다 가운데 없습니다 성공
지금 라이브              수집 진행률 99.8% — 요청 430 가운데 429 성공 · 실패 1
```

```
★ 01:01 은 제가 현황을 고치는 도중이었다 (v195 작업 중).
★ 이것이 ★ A-2 의 「반쪽 배포」가 왜 위험한지를 그대로 보여 준다 —
  템플릿은 저장하자마자 라이브에 반영되므로
  ★ 개발측이 편집 중인 화면을 가이드가 그대로 본다
★ 규격에 「작업 중에는 조사창으로 보지 않는다」가 없다.  넣어 주셔야 한다
```

## J-⑤ 「3,841 vs 3,137」 — 결함이 아니라 **밝히지 않은 것**이다

```
현황 3,841 = 판정 전건 (result_score · 필터 없음)
목록 3,137 = 기본 필터를 건 수
             ★ 리스·렌트를 뺀다 (개정 420 · report/screens/build.py:921)
             ★ 관문 배제(EXCLUDED)를 뺀다 (개정 433 · build.py:931)
             EXCLUDED 776건 · 리스 233 · 렌트 590
```

```
★ 둘 다 제 정의로는 맞다.  ★ 화면이 그 차이를 안 밝히는 것이 문제다
★ V11-165 는 「★ 뺀 건수도 밝힌다 — 조용히 빼면 매물이 사라진 것으로 보인다」다.
  목록에는 지켰는데 ★ 현황의 「3,841건 · 전 차종」에는 아무 말이 없다
★ 고칠 곳은 「건수를 맞추는 것」이 아니라 ★ 「현황에 한 줄 붙이는 것」이다
```

## J-⑦ 은 F-1 을 보시라 — 「A 인데」가 아니라 「EXCLUDED 인데」다

```
★ 「알파벳 순으로 센다」로 적으면 고칠 사람이 ★ 비교를 거꾸로 뒤집는다.
  그러면 A~G 끼리(84짝)가 전부 망가진다 — 지금 그건 맞기 때문이다
★ 진짜 고칠 것은 ★ GRADE_ORDER 색인으로 견주기다 (110짝 중 26짝이 어긋난다)
```
