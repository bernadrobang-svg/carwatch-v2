## 2. 무엇을 했나

### ① 원인 — 값이 많아서가 아니라 표가 쥐어짜여서다

먼저 데이터를 의심했는데 아니었다.

```
값 예시는 이미 5개로 잘려 있었다 — 48자
「프론트 휀더(좌) · 프론트 휀더(우) · 리어 도어(우) · 후드 · 쿼터 패널(우)」
```

**48자가 6열 표의 한 칸(약 40px)에 들어가 한 글자씩 떨어진 것이다.**
`main table { overflow-x:auto }` 만으로는 안 됐다 — 안쪽 표가 여전히
화면 폭에 맞춰 줄어들기 때문이다.

```css
main table > thead, main table > tbody {
  display:table; width:100%; min-width:520px;   /* ★ 이것이 빠져 있었다 */
}
main table td, main table th { word-break:keep-all; }
```

**안쪽에 최소 폭을 줘야 바깥이 가로로 넘어간다.** 이제 표 안에서만 넘긴다.

## 6. 못 한 것 · 막힌 것 · 판단이 필요한 것

### ① 관리 표를 「카드」로 바꾸지는 않았다 — 가로 넘김으로 했다

지시 3 은 「listings 처럼 카드로」였다. 카드로 바꾸려면 칸마다 `data-label` 이
있어야 하는데 관리 화면 17개의 표에 그것을 다 붙여야 한다.

```
지금   표 안에서만 가로로 넘긴다 (스크롤바가 보이게)
      ★ 글자가 세로로 떨어지는 것은 없어졌다 — V11-78 통과
```

`admin_dict` 처럼 **표 자체가 맞지 않는 화면은 접기로 바꾸는 것이 낫다**고 본다.
카드로 전면 전환할지, 화면마다 맞는 모양을 고를지 **지시를 부탁한다.**

### ② `V11-78` 은 브라우저를 안 쓴다 — 근사다

실제 픽셀을 재지 않고 「열 수 × 3글자 × 7px」로 어림한다.
정확히 재려면 스크린샷을 분석해야 하는데 그건 검사가 무거워진다.
**지금은 「최소 폭이 걸려 있는가」를 보는 것이 실질적인 방어다.**
