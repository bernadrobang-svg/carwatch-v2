## 4. 원인 넷 — 전부 규격 위반

### ① `S4`(목록 대조)가 재처리표에 없었다 — `collect/pipeline.py:99`

```
전   "listing_updated": Reprocess(None, ("S5","S6","S9","S10"), True)
규격  목록을 저장하면 → 대조 → 상세 → 새 5종 → 판정   (c-tools STEP 136g)
```

`S4` 가 목록 봉투를 펼쳐 `core_listing` 을 만드는 단계입니다. 그것이 빠져서
**받아 온 목록이 CORE 로 안 들어갑니다.**

### ② 전건 재수집 — 규격이 명시적으로 금지한 것

```
docs/chapters/60-admin/c-tools.md:988
  상세    ★ 새로 뜬 것 · 가격이 바뀐 것만.  전건이 아니다
  필수    ★ 목록 저장이 전건 재수집을 부르지 않는다
  근거    3,470건 × 9종 = 3만 호출이다.  매일 할 일이 아니다
```

`run.py:296 make_worker_executors()` 가 `resume` 을 안 넘겨 기본값 `False` 로
실행기를 만들었습니다. 그러면 S5 가 **이미 받은 것까지 전부** 다시 던집니다.
결정표의 `refetch` 값은 계산만 되고 **실행에 전달되지 않았습니다.**

### ③ ★ `V10-29` 가 그것을 못 잡았다 — 거짓 초록

```
검사 이름   「목록 저장이 전건 재수집을 안 부름」
보던 것     from_step 이 'S1','S2','S3' 인가
실제        from_step='S5' + 실행기 resume=False 로 전건이 나갔다
```

★ **금지된 일이 벌어지는데 검사는 초록이었습니다.** 이 프로젝트가 가장
경계하는 「선언과 실제의 괴리」입니다.

### ④ ★ S4 를 넣자 드러난 것 — S4 는 매번 중단한다

```
S4  expected 30,174  requested 3,309   상태 중단
    ↳ ⑥ not_requested 26,865건 — 미완성 매물이 남았다
```

S4 는 「더 새 관측이 있는 옛 봉투」를 의도적으로 건너뜁니다. 그런데 그것을
**`expected` 에서 안 빼서** `not_requested` 로 세고, `halt_if` 가 중단시킵니다.

★ 그래서 S4 를 체인에 넣자 **목록을 저장할 때마다 실패한 작업만 쌓였습니다**
(실패 63 → 128). S5 는 `done_before` 를 「expected 에서도 뺀다」로 이미 풀어
둔 문제인데 S4 에만 안 돼 있었습니다.
