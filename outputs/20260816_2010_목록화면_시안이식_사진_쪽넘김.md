### ① 시안 CSS 를 통째로 옮겼다 — 손으로 옮겨 적지 않았다


**옮기는 중에 두 가지가 걸렸다.**

`시안 23개가 같은 이름을 다르게 쓴다` — 실측 57개.
`.bar` 는 목록에선 필터 줄인데 `/why` 에선 진행 막대다. `.cand` 는 차종 화면에선
칩이고 추천 화면에선 카드다. `.prog`·`.log`·`.pol`·`.lead` 도 같다.
**평면으로 합치면 화면이 서로를 깨뜨린다.** 값이 갈리는 것만
`body.s-<화면>` 안에 가뒀다 — 화면 이름은 부분 템플릿 이름에서 자동으로 온다
(`listings.html` → `s-listings`). 손으로 적는 표를 만들지 않았다.

`@media 안의 규칙이 밖으로 샜다` — 1차 추출기가 중괄호를 세지 않아
`@media(max-width:980px){.grid{1fr}}` 의 안쪽이 **조건 없이** 걸렸다.
격자가 항상 1열이 될 뻔했다. 중괄호 깊이를 세도록 고치고 다시 뽑았다.

### ④ ★ 그러다 「후보 1건」의 진짜 원인을 찾았다 — 이것이 이번의 핵심

```
store/core.py   "SELECT MAX(calc_version) FROM result_score"
```

**`MAX` 는 글자 크기다. 판이 아니다.**

08-15 시험이 남긴 행 하나(`listing_id=3`, `calc_version='c3'`)가
`'c1'` 보다 글자가 커서 **전 화면이 c3 을 「지금 판」으로 읽고 있었다.**
c3 에는 채점이 1건뿐이다.

```
그래서 이렇게 보였다
  /recommend    후보 1건            ← 마스터가 본 것
  /listings     3,470행이 뜨는데 등급이 전부 비었다
  /listings?grade=B   1건           (실제로는 415건)
```

「가장 최근에 쓰인 판」으로 고쳤다 — `ORDER BY calculated_at DESC LIMIT 1`.
`'c10' < 'c9'` 도 같은 함정이라 나중에 반드시 터졌을 자리다.
`dict_version`·`parse_version` 도 같은 방식이었고 같이 고쳤다.

### ⑦ 시안 껍데기(header · nav)는 아직 우리 것이다

시안은 `.hwrap`·`.brand b`·`.hmeta`·`.sub`·`.swrap` 로 된 머리를 쓰는데
우리 `base.html` 은 `.top`·`.nav` 다. CSS 는 다 들어와 있고 **화면별로 가둬 놨다.**
`base.html` 을 시안 구조로 바꾸는 것은 전 화면에 영향이 가므로
**마스터가 지금 화면을 한 번 보신 뒤에 하는 것이 맞다고 판단했다.**
