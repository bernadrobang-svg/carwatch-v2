## 2 ★ 먼저 쟀다 — 두 가지가 규격과 다르다

### ① 머리·발은 **이미 한 곳**이다

```
틀 39개 중 <header>·<!DOCTYPE> 를 가진 것 — base.html 하나뿐
  (watch_invite.html 의 <header> 는 카드 속 머리지 쪽 머리가 아니다)
base.html 이 머리·발을 갖고 · _page.html 이 그것을 extends 하며
web/views.page() 가 모든 화면을 그것으로 감싼다
```

규격의 「틀 39개 중 include 를 쓰는 것이 셋뿐 · 머리·발을 화면마다 다시 쓴다」는
**지금 코드와 맞지 않습니다.** 「그래서 header 규칙이 23곳이 됐다」도 이미 닫혔습니다
(08-29 · 21곳 → 1곳 · S46-121).

### ② 틀 엔진에 `include` 가 **없었다**

```
web/template.py — RE_EXTENDS · RE_BLOCK 뿐.  {% include %} 는 아예 없다
```

규격이 쓰라고 적은 `{% include "_card.html" with r=row %}` 가 **안 도는 문법**이었습니다.
그래서 먼저 그것을 만들었습니다.

## 6 ★ 가이드께 — 나머지 조각 여섯은 그대로 못 뽑습니다

규격이 든 여덟 중 `_head`·`_foot` 은 위처럼 이미 한 곳이고, 나머지 여섯은
**글자가 화면마다 다릅니다.** 예를 들어 `_intro.html`(8곳) —

```
<div class="cond what">
  <h2>★ 이 화면은 무엇을 하는 곳인가</h2>     ← 이 두 줄만 같다
  <p>모든 사이트의 매물을 한 자리에서 본다…</p>  ← 화면마다 다르다
</div>
```

감싸개만 같고 속 글이 다릅니다. 지금 `include` 는 **값의 이름만 바꿉니다** —
HTML 덩어리를 넘겨 감싸는 기능(`{% block %}` 을 조각에 주는 것)은 없습니다.
길은 둘입니다 —

1. **속 글을 한 곳(예 `config/screen_intro.json`)으로 옮기고** 조각이 거기서 읽는다
2. `include` 에 **덩어리 넘기기**를 더 만든다 (엔진을 한 번 더 키운다)

★ 1 은 「시안 글자를 그대로 옮긴다 — 개발측이 새로 쓰지 않는다」와 부딪히지
않습니다(옮기는 것이지 고치는 것이 아닙니다). 다만 **시안 글이 틀에서 config 로
자리를 옮기는 일**이라 규칙 2 대로 여쭙고 합니다. **어느 쪽으로 갈까요.**

`_card`(카드 열일곱) · `_filter`(거르개 여섯) 도 같은 물음입니다.
