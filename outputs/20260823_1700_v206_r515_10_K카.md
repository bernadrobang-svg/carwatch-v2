# 2. ★ 상세는 받는다 — 규칙 넷을 세웠다

`tools/collect_kcar.py` ★ 신설

```
$ python3.11 tools/collect_kcar.py --check EC61393706 EC61377663 EC99999999
  EC61393706        73997B  정상
  EC61377663        80440B  정상
  EC99999999         3186B  ★ 없는 매물
★ 결과 — 정상 2 · 없는 매물 1 · 못 받음 0
★ acdtHistComnt — 무사고 2
```

## ① ★ 없는 매물도 200 이다 — ★ 셋으로 가른다

```
정상       carCd 가 있고 ★ 10,000B 이상
없는 매물   ★ 200 인데 carCd 가 ★ 없다 (3,186B) — ★ 사이트가 「없다」고 말한 것
못 받음     carCd 는 있는데 ★ 짧다 · 또는 응답을 못 읽었다
           ★ 이것을 「없음」으로 저장하지 않는다 (KB 봇페이지 2,759B 와 같은 함정)
```

## ② 사고는 `acdtHistComnt` 하나로 가른다

```
실측 2건   acdtHistComnt '무사고' · '무사고'
          ★ smplReprYn 1 · 1        ← ★ 둘 다 1 이다.  ★ 이것으로 가르면 안 된다
          ★ acdtHistYn  1 · 1        ← ★ 〃
★ 규격이 적은 그대로다.  ★ 넷째 값은 ★ 안 나왔다 (표본 2건 · 작다)
★ 넷째가 나오면 ★ 멈추고 알린다 — ★ 수집기가 exit 2 로 멈추게 해 뒀다
```

## ③ ★ `npriceFullType` 은 신차가가 ★ 아니다 — ★ 실측으로 확인했다

| carCd | `salprc` | `npriceFullType` | 견줌 |
|---|--:|--:|---|
| EC61393706 | 3,410 | 34,100,000 | ★ salprc × 10,000 |
| EC61377663 | 5,170 | 51,700,000 | ★ 〃 |

```
★ 규격이 맞다.  ★ 신차가로 쓰면 ★ 전 매물이 신차가 100% 가 된다
★ 신차가는 ★ 차종·트림 표에서 끌어온다 (f-table 「사이트별 채우기」)
```

## ④ 성능점검은 사진뿐이다 — ★ 감점을 안 준다

```
★ 사진을 안 읽고 골격·외판·누유를 판정하지 않는다.  ★ 사고차에 조용히 만점을 주지 않는다
★ 27축 매핑은 ★ 아직이다 (§4)
```
